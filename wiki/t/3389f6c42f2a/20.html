The unit evaluates TRACE against IRCoT, reporting indexing and inference runtimes on HotPotQA, 2WikiMultiHopQA, and MuSiQue using the same LLaMA3-7B model. TRACE has higher indexing latency because it generates knowledge-graph triples, but its inference runtime is similar to or lower than IRCoT because it selects triples with a single token rather than autoregressively generating multi-token thoughts. The unit also presents TRACE reasoning-chain examples involving The Wittenburg Door, Sports Collectors Digest, A Girl’s Gotta Do (What a Girl’s Gotta Do), and Mindy McCready. Additional examples show generated knowledge triples and reasoning chains for entities including Ellen Glasgow, Julian Barnes, Blaise Cendrars, Christina Stead, Nuruddin Farah, and Javi Martínez.

Efficiency Analysis We conduct experiments to evaluate the latency of TRACE in comparison to the baseline model IRCoT. Specifically, we conducted experiments on a 3.5 GHZ, 32-cores AMD Ryzen Threadripper Process paired with an NVIDIA A6000 GPU. Both TRACE and IRCoT use the same LLaMA3-7B model to generate thoughts or select triples. We report the average runtime, i.e., the average time for indexing one document (Indexing) and generating one thought or constructing one reasoning chain (Inference), on the development sets. The results are provided in Table 12. The results show that compared with IRCoT, TRACE has a higher indexing latency. This is because TRACE requires additional forward prop- agations through the LLaMA3-7B model to gener- ate KG triples. However, the construction of KG triples can be done offline. Once these triples are generated, they can be directly used to construct reasoning chains, facilitating the subsequent pro- cesses. Therefore, the cost of indexing does not impact the real-time efficiency during inference. Additionally, the results indicate that the in- ference runtime of TRACE is similar to IRCoT on HotPotQA and is even less on the other two datasets. This similarity arises because both TRACE and IRCoT use iterative methods to gen- erate reasoning chains and chain-of-thoughts, re- spectively. However, there are differences that im- pact the runtime: IRCoT requires the LLM to gen- erate thoughts, each containing multiple tokens. This process involves multiple forward propaga- tions through the LLM (i.e., the autoregressive gen- eration), which increase the latency.
