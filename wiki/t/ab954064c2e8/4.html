This section, in brief. The unit defines an ontology as a set of triples that represents entities, attributes, and values, where values may be other entities or unspecified domain values. It explains how ontology-mapped data is extracted from domain-specific documents and organized into self-contained factual-blocks that preserve contextual differences. The OG-RAG approach maps documents to an ontology, generates JSON-LD with GPT-4o, and uses a flattened hypergraph to answer queries such as which Soybean seeds are grown in Madhya Pradesh. The example returns JS335 and JS 95-60 as the relevant seed varieties.

Background An ontology is a formal representation of key enti- ties and their relationships within a domain. For ex- ample, in the agriculture domain, entities like crops, soil, and weather conditions are defined, along with relationships such as "crop is grown in a region" or "soil has moisture level". Earlier foundational efforts have led to the widespread standardization of domain-specific ontologies in many industries, such as healthcare 3 retail 4 , and energy 5. It differs from taxonomy or classifications as it allows for richer relationships between entities that need not be hierarchical. More formally, 3https://tinyurl.com/3e8pc2xr 4https://tinyurl.com/u5x2nck4 5https://tinyurl.com/4re4xekx Definition 1 An ontology O ⊆S ×A×(S ∪{ϕ}) consists of a set of triples that relate a set of entities S using a set of attributes A, where (s, a, v) ∈O denotes that the subject entity s has an attribute a, and the value v := vO(s, a) is either: (1) Another entity s′ ∈S, or (2) An unspecified domain value, denoted by ϕ. Here, v := vO(s, a) represents the value of the attribute a for entity s, which is either another entity within the ontology or an undefined (unspecified) text or data. For example, consider a subject entity s = “Crop”, that can have the attribute a1 = “is grown in”, which maps it to another object entity vO(s, a1) = s′ = “Crop Region”. Additionally, the same entity s can have another attribute a2 = “has name”, which maps it to an arbitrary text, de- noted as vO(s, a2) = ϕ, indicating that this value is unspecified and can be any relevant text or name in the domain. These unspecified values can thus be filled by extracting relevant knowledge from domain-specific documents D. However, different parts of the documents may provide distinct yet valid text/data values related to the same ontology entity. For example, one sec- tion may talk about Soybean crops grown in the Northwest region, while another talks about the one grown in the Northeast region. To represent this variability, we introduce factual blocks, each capturing a localized subject–attribute–value triple grounded in a specific context. This mechanism allows us to preserve the contextual distinction between values tied to the same ontology entity, avoiding overwriting or flattening these differences during grounding. Thus, ontology-mapped data represents self- contained and ontology-grounded information ex- tracted from domain-specific documents.
