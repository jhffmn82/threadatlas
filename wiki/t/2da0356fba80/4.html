The unit defines a standard RAG pipeline as consisting of an LLM G and a retriever R, such as BM25 or a dense retriever. Given a user query, the retriever selects the top k relevant documents, which the LLM uses with the query and an instruction to generate a response. A standard non-RAG LLM pipeline instead relies on knowledge stored in the model and uses a different instruction. The figure reports that most LLMs in the RAG setting produce a significantly higher percentage of unsafe responses than in the non-RAG setting.

Definitions A standard RAG pipeline contains two components: an LLM G and a retriever R, such as a sparse (e.g., BM25) (Robertson et al., 2009) or a dense retriever (Karpukhin et al., 2020). Given a user query q, the retriever R first retrieves the top k most relevant documents Dk = {d1, d2, . . . , dk} from a corpus. 5445 Figure 2: Safety of LLMs in non-RAG vs. RAG settings. Most LLMs in the RAG setting exhibit a significantly higher percentage of unsafe responses. These documents provide context for the LLM’s generation. Next, the language model G takes both the query q and the retrieved documents Dk as in- put to generate a response r = G(i L Dk L q), where i is the instruction such as “Answer the fol- lowing question. You should only use the following documents.” L denotes the template that concate- nates the instruction, documents, and query into a structured input for the model. In contrast, a standard (non-RAG) LLM pipeline depends on the knowledge stored in the model r = G(i′ L q) with a different instruction i′. 4
