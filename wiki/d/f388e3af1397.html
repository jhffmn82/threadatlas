TableRAG: A Retrieval Augmented Generation Framework for Heterogeneous Document Reasoning

Xiaohan Yu, Pu Jian, Chong Chen · 2025 · 20 sections
"TableRAG: A Retrieval Augmented Generation Framework for Heterogeneous Document Reasoning" by Xiaohan Yu, Jian Pu, Chong Chen (2025), licensed CC BY. Shown here as extracted text, with facts drawn from it. https://doi.org/10.18653/v1/2025.emnlp-main.710

The document presents TableRAG, an SQL-based framework for answering questions over heterogeneous documents that combine unstructured text and structured tables. It argues that conventional Retrieval-Augmented Generation can lose table structure and global context when tables are flattened, chunked, and treated as text, weakening performance on multi-hop and global questions. RAG is described as retrieving document chunks to improve LLM reliability, while prior table-reasoning methods include prompt-based and program-based approaches; heterogeneous text-table reasoning remains difficult. The task is to answer a question from extensive textual and tabular context. TableRAG preserves table structure through an offline phase that builds a textual knowledge base, tabular schema database, and relational database. In its online phase, it repeatedly decomposes a question into context-sensitive subqueries, retrieves relevant text, selectively generates and executes SQL, and composes intermediate answers. Iteration ends when no additional subqueries are needed, yielding a final answer. The document also introduces HeteQA, a benchmark for multi-hop reasoning across heterogeneous documents. Built using LLM generation together with human verification, it contains 304 examples based on Wikipedia tables and associated text, covering 136 tables, 5,314 wiki knowledge entities, nine semantic domains, and five main categories of tabular reasoning operations. Its examples may require single-source or multi-source evidence. Experiments compare TableRAG with Direct generation, NaiveRAG, ReAct, and TableGPT2 on HeteQA, HybridQA, and WikiTableQuestion, using several LLM backbones. TableRAG reports the strongest performance across these benchmarks and works on both single-source and multi-source questions. Ablations show that query decomposition, SQL execution, and text retrieval each contribute, with differing importance across benchmarks. Efficiency results attribute lower latency than ReAct, including with Qwen-72B-Instruct, to fewer iterations and symbolic SQL execution: about 63.55% of instances finish in fewer than five steps and another 30.00% in exactly five. Error analysis distinguishes reasoning failures from incomplete tasks, such as SQL errors, poor decomposition, refusals, and iteration-limit failures. TableRAG has the lowest failure rate and produces valid responses within five iterations, though Qwen-backed results are weaker in Culture, possibly because of sparse instances. The document concludes that TableRAG improves heterogeneous reasoning but depends on capable LLMs, while HeteQA is currently limited to English.

Abstract body

The text concerns TableRAG, an SQL-based framework for question answering over heterogeneous documents containing textual and tabular components. It addresses limitations of existing Retrieval-Augmented Generation approaches, whose table flattening and chunking can disrupt structure, cause information loss, and weaken large language models on multi-hop and global queries. TableRAG performs context-sensitive query decomposition, text retrieval, SQL programming and execution, and compositional intermediate answer generation. The authors also introduce HeteQA to evaluate multi-hop heterogeneous reasoning and report that TableRAG outperforms existing baselines on public datasets and HeteQA.

The unit concerns heterogeneous document-based question answering over unstructured text and structured tables. It identifies structural information loss and lack of a global view as limitations of retrieval-augmented generation when tables are linearized, chunked, and retrieved as text. It introduces TableRAG, an SQL-based framework that combines text retrieval with SQL programming and execution through iterative reasoning. It also presents HeteQA, a benchmark of 304 examples across nine domains for evaluating multi-hop reasoning over heterogeneous documents.

The heterogeneous document question answering task concerns answering a user question using extensive documents. These documents contain textual contents and tabular components. The task defines a function F that takes the combined textual and tabular context along with the question and produces the correct answer.

3 / 3.1 .. 3.3 body

TableRAG is an SQL-based framework for preserving table structural integrity and supporting reasoning across textual and tabular information. Its offline phase constructs a textual knowledge base, a tabular schema database, and a relational database from heterogeneous documents. Its online phase iteratively performs context-sensitive query decomposition, text retrieval, selective SQL programming and execution, and compositional intermediate answer generation. The process continues until no further subqueries are needed, producing a final answer.

4 / 4.1 .. 4.2 body

This unit introduces HeteQA, a benchmark for evaluating multi-hop reasoning across heterogeneous documents. Its data collection pipeline combines LLMs with human verification to generate, execute, inspect, and document-reference complex queries over Wikipedia tables and associated text. HeteQA contains 304 examples grounded in single-source or multi-source evidence, spanning 136 tables and 5314 wiki knowledge entities. The benchmark covers nine semantic domains and five principal categories of tabular reasoning operations.

5 / 5.1 / 5.1.1 .. 5.3 body

The unit evaluates TableRAG on HeteQA, HybridQA, and WikiTableQuestion using several LLM backbones and compares it with Direct generation, NaiveRAG, ReAct, and TableGPT2. TableRAG achieves the strongest reported performance across the benchmarks and remains effective on both single-source and multi-source questions. An ablation study finds that context-sensitive query decomposition, SQL execution, and textual retrieval all contribute to performance, with their relative importance varying by benchmark. A latency analysis further reports that TableRAG is faster than ReAct on WikiTQ and HeteQA.

6 / 6.1 .. 6.2 body

This unit evaluates TableRAG’s execution efficiency and latency against TableGPT2 and ReAct. TableRAG resolves approximately 63.55% of instances in fewer than five steps and an additional 30.00% precisely within five, with few cases remaining unsolved under the iteration constraints. TableRAG also achieves lower latency than ReAct when Qwen-72B-Instruct is used as the backbone, owing to fewer iterations and computationally efficient symbolic SQL execution. The results attribute TableRAG’s efficiency and reasoning accuracy to its SQL-based tabular reasoning.

7 / 7.1 .. 7.2 body

The unit analyzes TableRAG’s errors and compares it with TableGPT2 and ReAct on HeteQA. It classifies incorrect outputs as reasoning failures or task incompletion, including SQL errors, flawed query decomposition, refusals, and exceeding the iteration limit. TableRAG has the lowest failure rate and consistently produces valid responses within five iterations, while TableGPT2 and ReAct show different limitations. Across domains, TableRAG generally outperforms ReAct, although its Qwen-backed performance is weaker in Culture, possibly because of sparse domain-specific instances.

8 / 8.1 .. 8.2 body

Retrieval-Augmented Generation (RAG) is presented as a paradigm for mitigating hallucination and improving the reliability of Large Language Models (LLMs) by retrieving relevant document chunks from a knowledge base. The text notes that conventional retrieval can produce noisy or incomplete context, motivating task-adaptive approaches such as Self-RAG and RQ-RAG, while heterogeneous contexts remain challenging. Table reasoning concerns answering user queries from tabular data and is divided into prompt-engineering approaches and program-based approaches. Examples include Tab-CoT and Chain-of-Table for structured reasoning, and Tabsqlify, DATER, BINDER, and InfiAgent-DABench for processing tables with SQL, Python, agents, or related techniques.

9 body

This unit concludes that existing RAG approaches struggle with heterogeneous documents containing textual and tabular data because they compromise table structure and impair global, multi-hop reasoning. It presents TableRAG as an SQL-driven framework that combines textual understanding with precise tabular manipulation. It also introduces HeteQA, a benchmark for evaluating these capabilities, and reports that TableRAG outperforms existing baselines on public datasets and HeteQA. The unit notes that TableRAG depends on capable underlying LLMs and that HeteQA is currently limited to English.
