RAGAS: Automated Evaluation of Retrieval Augmented Generation

Shahul Es, Jithin James, Luis Espinosa-Anke, Steven Schockaert · 2024 · 18 sections
"RAGAs: Automated Evaluation of Retrieval Augmented Generation" by Shahul Es, Jithin James, Luis Espinosa-Anke, Steven Schockaert (2024), licensed CC BY. Shown here as extracted text, with facts drawn from it. https://doi.org/10.18653/v1/2024.eacl-demo.16

This document presents RAGAS, Retrieval Augmented Generation Assessment, a reference-free framework for evaluating Retrieval Augmented Generation pipelines. RAG systems retrieve passages from a reference corpus and give them, along with a question, to a language model, helping address information that is post-training or rare in training data. The paper argues that evaluating such systems is difficult: perplexity may not reflect downstream performance, closed models may not expose probabilities, and conventional evaluation often requires reference answers or human annotation. RAGAS focuses on three central dimensions: faithfulness, answer relevance, and context relevance. Faithfulness measures whether statements in a generated answer are supported by retrieved context; the framework extracts focused statements from answer sentences and uses an LLM-based verification function to determine support. Answer relevance is estimated by generating questions from the answer and comparing their embeddings to the original question using text-embedding-ada-002 and cosine similarity. Context relevance measures the proportion of retrieved context sentences judged necessary to answer the question. The reported implementation and experiments use gpt-3.5-turbo-16k, with prompts and structured outputs supporting the metrics. The document situates RAGAS among other approaches to factuality and text-generation evaluation, including prompting, token probabilities, hidden states, multiple-answer sampling, SelfCheckGPT, BARTScore, BERTScore, and MoverScore. It then introduces WikiEval, a dataset of question-context-answer triples with human judgments. Built from 50 Wikipedia pages about events since the start of 2022, especially pages with recent edits, WikiEval uses questions formulated from introductory sections and includes answers produced with and without context as well as lower-relevance candidates. Human annotators judged the three dimensions, with about 95% agreement for faithfulness and context relevance and about 90% for answer relevance. Experiments compare RAGAS with GPT Score and GPT Ranking through pairwise comparisons against WikiEval judgments. RAGAS aligns more closely with humans, particularly on faithfulness and answer relevance, while context relevance is the hardest dimension. JSON-formatted outputs improve reproducibility, though randomness, undocumented API changes, and structured-output requirements remain challenges. RAGAS is provided through a Python API, with example evaluation on Amnesty QA and default OpenAI API metrics. The paper concludes that RAGAS and WikiEval support faster end-to-end RAG evaluation, while acknowledging dependence on LLM quality and urging careful model selection, ideally including open models.

Abstract body

The text introduces RAGAS (Retrieval Augmented Generation Assessment), a framework for evaluating Retrieval Augmented Generation pipelines without reference annotations. It concerns RAG systems, which combine a retrieval module with an LLM-based generation module and provide large language models with knowledge from a reference corpus. RAGAS evaluates retrieval quality, the faithful use of retrieved passages, and the quality of generated responses through a suite of reference-free metrics. The framework is intended to support faster evaluation cycles for RAG architectures.

opening body

The text explains that language models struggle with post-training events and knowledge that is rarely mentioned in their training corpus. Retrieval Augmented Generation addresses these issues by retrieving relevant passages and providing them to a language model with the original question. Evaluating RAG systems requires tuning and is often difficult because perplexity may not predict downstream performance and closed models may not expose probabilities. The paper presents RAGAS, a framework for automatically assessing retrieval-augmented generation systems without requiring reference answers.

2 / Estimating faithfulness using LLMs .. Automated evaluation of text generation systems body

This unit reviews methods for estimating the faithfulness and factuality of LLM-generated responses, including prompting, token probabilities, hidden states, and sampling multiple answers. It describes BARTScore, Kadavath et al.'s multiple-choice approach, Azaria and Mitchell's hidden-state classifier, and SelfCheckGPT. It also surveys LLM-based evaluation of fluency and other text-generation qualities, including direct scoring and candidate selection. Finally, it discusses reference-based metrics such as BERTScore, MoverScore, and BARTScore.

3 .. Faithfulness body

The unit describes evaluation strategies for retrieval-augmented generation (RAG) systems without human-annotated datasets or reference answers. It identifies faithfulness, answer relevance, and context relevance as central quality aspects, with faithfulness concerning whether a generated answer is grounded in the retrieved context. It explains that large language models can be prompted to measure these aspects automatically, using gpt-3.5-turbo-16k in the reported implementation and experiments. For faithfulness, the system first extracts focused statements from each sentence of the generated answer so they can be checked against the context.

opening .. Context relevance body

The unit describes how an LLM evaluates whether statements in an answer can be inferred from a question's context using a verification function. It defines the faithfulness score as the proportion of supported statements and explains how answer relevance is estimated by generating questions from an answer and comparing their embeddings with the original question. It also defines context relevance as the proportion of context sentences extracted as necessary for answering the question. The procedures use specified prompts and, for answer relevance, the text-embedding-ada-002 model and cosine similarity.

4 body

The WikiEval Dataset was created to evaluate the proposed framework using question-context-answer triples with human judgments. The dataset is intended to assess faithfulness, answer relevance, and context relevance, and to compare these judgments with the framework’s metrics. Its creators selected 50 Wikipedia pages about events since the start of 2022, prioritizing pages with recent edits. ChatGPT was then asked to formulate questions answerable from each page’s introductory section.

notes notes

opening body

The unit describes quality guidelines for generating questions and evaluates answers in the WikiEval dataset. ChatGPT was used to answer questions with and without context and to generate candidate answers with lower answer relevance. Human annotators assessed faithfulness, answer relevance, and context relevance, achieving about 95% agreement for faithfulness and context relevance and about 90% for answer relevance. The unit presents examples involving the film Oppenheimer and the PSLV-C56 mission.

5 .. 5.1 body

The Experiments section evaluates RAGAS metrics against human assessments from the WikiEval dataset using pairwise comparisons of faithfulness, answer relevance, and context relevance. RAGAS agrees more closely with human annotators than the GPT Score and GPT Ranking baselines, while context relevance is identified as the hardest dimension to evaluate. The reproducibility analysis finds that JSON-formatted outputs make RAGAS scores more consistent across successive runs. The unit also discusses challenges caused by randomness, undocumented API changes, and structured-output requirements when using large language models.

6 body

RAGAS provides access to metrics and datasets through an easy-to-use Python API. The unit shows how to load the Amnesty QA dataset, evaluate its evaluation split with faithfulness, answer relevancy, and context relevancy metrics, and export the results to a pandas dataframe. The metrics available at ragas.metrics use OpenAI's API by default, although other LLMs can also be used for evaluation.

7 body

The unit concludes that automated reference-free evaluation is needed for RAG systems. It proposes an evaluation framework covering faithfulness, answer relevance, and context relevance. It introduces WikiEval, a dataset containing human judgements of these aspects, and describes RAGAS, an implementation of them. Evaluation on WikiEval found that RAGAS predictions closely aligned with human judgments, especially for faithfulness and answer relevance.

8 body

The paper has a section titled “Limitations.” This section states that the paper introduces a toolkit. The toolkit is aimed at providing an end-to-end evaluation framework for RAG.

notes notes

opening body

RAGAS relies heavily on the performance of LLMs to evaluate different components. The experiments show that its metrics have a high correlation with human judgements, but LLM limitations remain a concern. The text calls for careful review of LLM suitability, ideally prioritizing open models over paid APIs, for RAGAS and related contributions. RAGAS will continue encouraging fair systems built on top of it as more users gain access to accurate RAG systems.
