BlendFilter: Advancing Retrieval-Augmented Large Language Models via Query Generation Blending and Knowledge Filtering

Haoyu Wang · 2024-11 · 15 sections
"BlendFilter: Advancing Retrieval-Augmented Large Language Models via Query Generation Blending and Knowledge Filtering" by Haoyu Wang, Ruirui Li, Haoming Jiang, Jinjin Tian, Zhengyang Wang, Luo Chen, Xianfeng Tang, Monica Xiao Cheng, Tuo Zhao, Jing Gao (2024), licensed CC BY. Shown here as extracted text, with facts drawn from it. https://doi.org/10.18653/v1/2024.emnlp-main.58

Abstract written by a model

This unit presents BlendFilter, a retrieval-augmented generation framework for Generative Large Language Models in knowledge-intensive, open-domain question answering. It addresses two central problems: complex, multifaceted inputs can cause direct retrieval to miss needed evidence, and retrieved documents can contain irrelevant or harmful noise that weakens answers. The unit first reviews LLM-assisted retrieval approaches, question decomposition, query rewriting, and query augmentation, and their limitations, including misleading sub-questions, training costs, and dependence on one augmentation source. BlendFilter instead works without fine-tuning, using a pre-trained Large Language Model, a knowledge base, and a retriever. It blends the original query with externally knowledge-augmented and internally knowledge-augmented queries. It retrieves knowledge for the original and augmented queries, filters each set independently through a self-reliant module that uses the LLM’s own capabilities to remove extraneous content, combines the retained knowledge, and generates an answer using Chain-of-Thought reasoning. Evaluation on HotPotQA, 2WikiMultiHopQA, and StrategyQA uses GPT3.5-turbo-Instruct, Vicuna 1.5-13b, and Qwen-7b. BlendFilter consistently surpasses retrieval-augmented and state-of-the-art baselines across datasets and backbones, including when BM25 replaces ColBERT v2. Its query blending and filtering improve retrieval precision, recall, and S-Precision; removing any original, external, or internal query source reduces performance. Retrieving more documents helps initially but can slightly hurt later, while multiple answer samples help all methods but benefit BlendFilter less. The principal limitation is tuning K, the number of retrieved documents, though performance is not highly sensitive to it. The work acknowledges support from the US National Science Foundation through NSF IIS-1747614 and NSF IIS-2141037.

Abstract body

The unit concerns Retrieval-augmented Large Language Models (LLMs) and their use in knowledge-intensive scenarios. It introduces BlendFilter, an approach that combines query generation blending with knowledge filtering to address complex inputs and noisy retrieval. BlendFilter integrates external and internal knowledge with the original query and uses the LLM’s intrinsic capabilities to remove extraneous data. Experiments on three open-domain question-answering benchmarks show that BlendFilter significantly surpasses state-of-the-art baselines.

1 body

The unit concerns Generative Large Language Models and retrieval-augmented generation for improving answers to complex questions. It explains that direct retrieval can miss essential information when task inputs are multifaceted, motivating query decomposition, rewriting, and augmentation. It introduces BlendFilter, which blends original, external knowledge-augmented, and internal knowledge-augmented queries and filters irrelevant retrieved knowledge without an extra language model. Experiments on three open-domain question answering benchmarks show that BlendFilter surpasses baseline models across three backbones.

2 body

The unit reviews retrieval-augmented generation methods that use Large Language Models (LLMs) to interact more actively with retrievers. It categorizes LLM-assisted retrieval into question decomposition, query rewriting, and query augmentation, while describing limitations such as misleading sub-questions, training costs, and reliance on a single augmentation source. It also discusses knowledge filtering methods designed to prevent irrelevant or harmful retrieved knowledge from degrading answers. The figure presents BlendFilter as a framework combining internal and external knowledge augmentation, knowledge filtering, and answer generation.

3 .. 3.4 body

The methodology uses a pre-trained Large Language Model, a knowledge base, and a retriever to improve responses without fine-tuning. BlendFilter combines query generation blending with knowledge filtering, using external and internal knowledge augmentation to produce enhanced queries. Retrieved knowledge is filtered independently for the original and augmented queries before being combined. The Large Language Model then generates an answer from the filtered knowledge using Chain-of-Thought reasoning.

4 .. 4.8 body

The unit evaluates BlendFilter against retrieval-augmented baselines on HotPotQA, 2WikiMultiHopQA, and StrategyQA using GPT3.5-turbo-Instruct, Vicuna 1.5-13b, and Qwen-7b. BlendFilter consistently improves performance across backbones and datasets, and it also outperforms baselines when BM25 replaces ColBERT v2. Its query blending and knowledge filtering improve retrieval precision, recall, and S-Precision, while removing any of its original, externally augmented, or internally augmented queries reduces performance. Increasing the number of retrieved documents initially helps and then slightly hurts performance, while sampling multiple answers benefits all methods but produces smaller gains for BlendFilter.

5 body

The paper introduces BlendFilter, a framework for enhancing retrieval-augmented generation within LLMs. It combines query generation blending with knowledge filtering to address complex inputs and reduce noise in retrieved knowledge. Its self-reliant knowledge filtering module uses an LLM’s capabilities to remove extraneous content, while external and internal knowledge augmentation support retrieval. Experiments on three benchmarks show that BlendFilter outperforms state-of-the-art baselines and generalizes to GPT3.5-turbo-Instruct, Vicuna 1.5-13b, and Qwen-7b.

Limitations body

The unit describes a limitation of the BlendFilter framework concerning the hyper-parameter K. K controls how many documents the framework needs to retrieve and may require additional tuning effort. However, model performance is not very sensitive to K, so the paper fixes it at a value that achieves good performance.
