In TurboRAG, it is computed offline for each document or passage chunk, stored in a database or on disk, and later retrieved for relevant text. front matter .. TurboRAG: Accelerating Retrieval-Augmented Generation with Precomputed KV Caches for Chunked Text

Precomputed KV caches are identified as the mechanism used by TurboRAG to accelerate retrieval-augmented generation.

1 / Introduction .. Contributions

Frequently retrieved chunks require KV cache computation on every conventional RAG query. TurboRAG precomputes and stores a KV cache for each passage, then retrieves and stitches the relevant caches during inference.

2 / Related Work

KV caches can be compressed, selectively evicted, or reused to accelerate language-model inference. TurboRAG precomputes passage-level KV caches and stitches them using reordered positional semantics, while RAG-Cache requires an exact context match and CacheBlend precomputes per-passage caches.

3 / Methodology .. 3.4 / The TurboRAG Pipeline

A KV cache stores transformed key and value representations for context tokens so they can be reused during later autoregressive decoding. TurboRAG computes document KV caches offline, stores them in a database, retrieves the relevant caches, and concatenates them online.

4 / Experiments .. 4.5 / Batch Scaling

TurboRAG shifts KV-cache computation for each document to offline processing, reducing online computation overhead for long text. The KV cache must be transferred from CPU to GPU in the tested deployment setting, although prefetching it to GPU memory removes the communication component from the comparison.

5 / Conclusion and Discussion .. Limitations

The KV cache is pre-computed for retrieved text fragments and concatenated for use during generation. Its storage and loading requirements create deployment pressure, although quantization and compression can reduce its footprint.
