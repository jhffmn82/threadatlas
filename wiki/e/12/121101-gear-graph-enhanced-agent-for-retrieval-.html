  • In GEAR: Graph-enhanced Agent for Retrieval-augmented Generation: This is an ACL 2025 paper, “GEAR: Graph-enhanced Agent for Retrieval-augmented Generation,” by Zhili Shen and colleagues at Huawei Technologies Co., Ltd. It presents GEAR, a retrieval-augmented generation framework for open-domain multi-hop question answering, where answering requires evidence from several passages. The paper’s central components are SyncGE, a graph-enhanced retriever, and an agentic multi-step retrieval process with memory, answer assessment, and query rewriting. GEAR represents passages through associated triples: each triple is linked to one passage, while passages may contain multiple triples. A large language model summarizes retrieved passages into proximal triples, connects them to a triple graph, and uses Diverse Triple Beam Search with a generic semantic model to expand multiple relevant paths. This avoids repeatedly prompting an LLM to traverse the graph. Across iterations, GEAR stores a gist memory of the multi-hop context, determines whether the evidence can answer the original question, and, if necessary, rewrites the query for further retrieval. When it terminates, it maps memorized triples back to passages and fuses these with previously retrieved passages through Reciprocal Rank Fusion. The paper situates GEAR against query-expansion, iterative retrieval-and-prompting, offline-indexing, and graph-based systems such as IRCoT, GraphReader, TRACE, and HippoRAG, arguing that existing approaches can face issues with updates, filtering, predefined concepts, or semantic relationships. Experiments on MuSiQue, HotpotQA, and 2Wiki-MultiHopQA use Recall@5, Recall@10, Recall@15, Exact Match, and F1. GEAR reports state-of-the-art multi-step retrieval, including R@15 of 71.5 on MuSiQue, 95.9 on 2Wiki-MultiHopQA, and 97.3 on HotpotQA, with gains exceeding 10% on MuSiQue. It also achieves the best listed end-to-end QA EM and F1 using five passages. Analysis finds that SyncGE improves all tested base retrievers, diverse triple beams outperform standard beam search, and retrieval recall positively correlates with QA performance. GEAR is especially effective for low-to-moderate-complexity questions and uses fewer iterations and LLM tokens than HippoRAG w/ IRCoT. The paper closes by noting possible improvements in entity disambiguation, knowledge graph completion, triple scoring, gist memory, reasoning, and query rewriting.

Abstract

The unit concerns GEAR, a system designed to improve Retrieval-augmented Generation (RAG) for multi-hop retrieval scenarios. GEAR introduces an efficient graph expansion mechanism that augments conventional base retrievers such as BM25, along with an agent framework that integrates graph-based retrieval into a multi-step retrieval framework. Across three multi-hop question answering datasets, GEAR demonstrates superior retrieval capabilities, including state-of-the-art results and improvements exceeding 10% on MuSiQue. It also consumes fewer tokens and requires fewer iterations than existing multi-step retrieval systems.

Introduction

The introduction presents GEAR, a Graph-enhanced Agent for Retrieval-augmented generation, for multi-hop Question Answering that requires reasoning across several passages or documents. GEAR’s SyncGE retriever uses an LLM to locate initial triples and a generic semantic model to expand diverse triple beams without recursively prompting an LLM for graph traversal. GEAR also constructs a memory from multi-hop context to support multi-step retrieval. On MuSiQue, HotpotQA, and 2WikiMultihopQA, GEAR achieves state-of-the-art retrieval performance, including gains exceeding 10% on MuSiQue, while using fewer iterations and significantly fewer LLM tokens.

The authors propose a graph-based retrieval framework that aligns passages with extracted triples and uses a small semantic model to explore multi-hop relationships.

Retrieval with Synchronised Graph .. Reasoning for Termination / Query Re-writing / After Termination

The unit describes GEAR, which combines Synchronised Graph Expansion with a multi-step agentic framework for retrieving passages connected through triples. Knowledge synchronisation uses a large language model to summarize passages into proximal triples, which are linked to triples in the graph and expanded with Diverse Triple Beam Search. GEAR maintains a gist memory, assesses whether the accumulated evidence answers the original query, and rewrites the query when further retrieval is needed. After termination, it links memorized triples to passages and combines these with passages retrieved across iterations using Reciprocal Rank Fusion.

Experimental Setup .. Baselines / Implementation Details

The unit evaluates GEAR on the open-domain multi-hop question answering datasets MuSiQue, HotpotQA, and 2Wiki-MultiHopQA. It measures retrieval with Recall@5, Recall@10, and Recall@15, and evaluates question answering with Exact Match and F1. GEAR outperforms the listed single-step and multi-step baselines in retrieval, reaching R@15 scores of 71.5 on MuSiQue, 95.9 on 2Wiki-MultiHopQA, and 97.3 on HotpotQA. The experiments use GPT-4o mini at temperature 0 for methods requiring an LLM and for triple extraction.

Results

The unit reports that GEAR achieves state-of-the-art performance in multi-step retrieval across MuSiQue, 2Wiki, and HotpotQA, with gains exceeding 10% over competitors on MuSiQue. SyncGE improves single-step retrieval, and Hybrid + SyncGE reaches state-of-the-art performance on MuSiQue and HotpotQA. The analysis finds a positive correlation between retrieval recall and question answering performance. In end-to-end QA with the top five retrieved passages, GEAR achieves the highest EM and F1 scores among the listed retrievers.

Discussion / What makes GEAR work? .. Is GEAR efficient?

The unit examines what makes GEAR effective, how robust it is, and whether it is efficient. SyncGE improves every base retriever across MuSiQue, 2Wiki, and HotpotQA, while Diverse Triple Beam Search consistently improves recall over standard beam search. GEAR achieves strong retrieval performance in one iteration, performs especially well on low-to-moderate-complexity questions, and remains consistent across passages with different triple densities. Compared with HippoRAG w/ IRCoT, GEAR requires fewer iterations and fewer LLM tokens, while SyncGE outperforms a more LLM-heavy solution on MuSiQue.

Conclusion

The unit introduces GEAR, a framework that incorporates a graph-based retriever into a multi-step retrieval agent for multi-hop question answering. Its graph retriever, SyncGE, uses the large language model to synchronize passage information with triples and expand the graph through diverse beams of triples linking multi-hop contexts. GEAR also constructs a gist memory from contexts returned by SyncGE to summarize information across iterations. Experiments show that GEAR outperforms other multi-step retrieval methods while using fewer iterations and large language model tokens.

Limitations

This paper examines retrieval using a graph of triples that bridge corresponding passages. It demonstrates the effectiveness of its graph expansion approach and GEAR, while noting that graph construction could be improved through entity disambiguation and knowledge graph completion. The scoring function in the diverse triple beam search uses a dense embedding model, though natural language inference is proposed as an alternative. The paper also identifies opportunities to improve the gist memory, reasoner, and query rewriter through more specialized designs.
