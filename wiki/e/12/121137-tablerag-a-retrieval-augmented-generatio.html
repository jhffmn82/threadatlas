The document presents TableRAG, an SQL-based framework for answering questions over heterogeneous documents that combine unstructured text and structured tables. It argues that conventional Retrieval-Augmented Generation can lose table structure and global context when tables are flattened, chunked, and treated as text, weakening performance on multi-hop and global questions. RAG is described as retrieving document chunks to improve LLM reliability, while prior table-reasoning methods include prompt-based and program-based approaches; heterogeneous text-table reasoning remains difficult. The task is to answer a question from extensive textual and tabular context. TableRAG preserves table structure through an offline phase that builds a textual knowledge base, tabular schema database, and relational database. In its online phase, it repeatedly decomposes a question into context-sensitive subqueries, retrieves relevant text, selectively generates and executes SQL, and composes intermediate answers. Iteration ends when no additional subqueries are needed, yielding a final answer. The document also introduces HeteQA, a benchmark for multi-hop reasoning across heterogeneous documents. Built using LLM generation together with human verification, it contains 304 examples based on Wikipedia tables and associated text, covering 136 tables, 5,314 wiki knowledge entities, nine semantic domains, and five main categories of tabular reasoning operations. Its examples may require single-source or multi-source evidence. Experiments compare TableRAG with Direct generation, NaiveRAG, ReAct, and TableGPT2 on HeteQA, HybridQA, and WikiTableQuestion, using several LLM backbones. TableRAG reports the strongest performance across these benchmarks and works on both single-source and multi-source questions. Ablations show that query decomposition, SQL execution, and text retrieval each contribute, with differing importance across benchmarks. Efficiency results attribute lower latency than ReAct, including with Qwen-72B-Instruct, to fewer iterations and symbolic SQL execution: about 63.55% of instances finish in fewer than five steps and another 30.00% in exactly five. Error analysis distinguishes reasoning failures from incomplete tasks, such as SQL errors, poor decomposition, refusals, and iteration-limit failures. TableRAG has the lowest failure rate and produces valid responses within five iterations, though Qwen-backed results are weaker in Culture, possibly because of sparse instances. The document concludes that TableRAG improves heterogeneous reasoning but depends on capable LLMs, while HeteQA is currently limited to English.

Abstract

The text concerns TableRAG, an SQL-based framework for question answering over heterogeneous documents containing textual and tabular components. It addresses limitations of existing Retrieval-Augmented Generation approaches, whose table flattening and chunking can disrupt structure, cause information loss, and weaken large language models on multi-hop and global queries. TableRAG performs context-sensitive query decomposition, text retrieval, SQL programming and execution, and compositional intermediate answer generation. Retrieval-Augmented Generation (RAG) is presented as a paradigm for mitigating hallucination and improving the reliability of Large Language Models (LLMs) by retrieving relevant document chunks from a knowledge base. The text notes that conventional retrieval can produce noisy or incomplete context, motivating task-adaptive approaches such as Self-RAG and RQ-RAG, while heterogeneous contexts remain challenging. Table reasoning concerns answering user queries from tabular data and is divided into prompt-engineering approaches and program-based approaches. Examples include Tab-CoT and Chain-of-Table for structured reasoning, and Tabsqlify, DATER, BINDER, and InfiAgent-DABench for processing tables with SQL, Python, agents, or related techniques.
