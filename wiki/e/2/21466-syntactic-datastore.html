syntactic datastore

datastore · 1 work · 8 quoted facts · 2 connections
Also called: both datastores, syntactic datastore (kNN-TRANX), syntactic knowledge stored

Abstract written by a model

The syntactic datastore is a separate kNN-TRANX datastore for syntactic knowledge, built by AST node type alongside a semantic datastore. It stores context representations as keys and target rules as values, holding structural information for AST-node retrieval. When grammar indicates that a syntactic node, or a subsequent syntactic token, should be predicted, it retrieves a small number of syntactic nearest neighbors, capped at Krule = 4. It contains 109 token types and 1,603k entries. Separation reduces retrieval noise and accommodates different vocabulary sizes; even limited syntactic knowledge can support high-quality code generation and improve performance. During canonical incremental adaptation, it updates with the semantic datastore when Only Semantics is false.

5 sections; each heading opens the text

1

The syntactic datastore is one of two separate datastores constructed by kNN-TRANX according to AST node type. It is queried when the grammar indicates that a syntactic node should be predicted.

3 / 3.1 .. 3.2

The syntactic datastore stores context representations as keys and target rules as values. It is retrieved when the subsequent token is expected to represent syntactic information.

4 / 4.1 .. 4.3

The syntactic datastore stores syntactic information separately from the semantic datastore because the two datastores have substantially different vocabulary sizes. Its upper retrieval limit is set to Krule = 4, and a small amount of stored syntactic knowledge can already support high-quality code generation.

opening

The syntactic datastore contains 109 token types and 1,603k entries. The text reports that even a small amount of syntactic knowledge can improve model performance.

6

The syntactic datastore is one of the datastores provided for the kNN-TRANX seq2tree model. In canonical incremental adaptation, it is updated simultaneously with the semantic datastore when Only Semantics is false, but is not the datastore updated when Only Semantics is true.
