Also called: reader component, sequence-to-sequence reader

Abstract written by a model

Reader is a component in research TableQA pipelines and a transformer-based sequence-to-sequence model. It linearizes each retrieved table with structure-aware header and row markers, uses the TaPEx tokenizer, and generates an answer per table. Jointly trained with the retriever using table-level signals, it first emits a binary token indicating table relevance, then produces the answer.

reader is in one work on this site, LI-RAGE: Late Interaction Retrieval Augmented Generation with Explicit Signals for Open-Domain Table Question Answering. This is the abstract a model wrote of it from that work.

Abstract

It is jointly trained with the retriever using explicit table-level signals. It generates answers with a binary relevance token prefixed to them.

Introduction

The reader generates answers from each retrieved table. It does not always rank answers from the gold table first, so the proposed training modification prepends binary relevance tokens indicating whether a table is relevant to the question.

A / Table Linearization

The reader component uses structure-aware separation to linearize the table. Its example includes [HEAD] for the header and [ROW] for table rows.
