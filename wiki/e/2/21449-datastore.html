Abstract written by a model

The datastore is a set of key-value pairs used in retrieval-based code generation. It stores decoder hidden states or representations as keys and corresponding target tokens or characters as values. In kNN-TRANX, two separate datastores hold syntactic and semantic knowledge; keeping these actions separate avoids retrieval noise, while combining them substantially reduces generated-code quality. During inference, one of the two datastores is retrieved through FAISS similarity search at each time step to support token generation, with syntax constraints guiding retrieval. Larger datastores improve generated-code quality. The datastore can be updated with mined CoNaLa data, using either both datastores or only the semantic datastore, enabling efficient fine-tuning with 17k trainable parameters instead of all 122,205k parameters. Switching datastores enables rapid updates, though additional datastores consume storage space that can grow with training data.

Syntax-Aware Retrieval Augmented Code Generation / Abstract

It is searched to support retrieval-based generation, and kNN-TRANX uses smaller datastores tailored to code generation. Syntax constraints are used to guide datastore retrieval and reduce the impact of retrieval noise.

2 / 2.1 .. 2.2

The datastore is built from key-value pairs in which each key is a decoder hidden state and each value is its corresponding target token. During inference, kNN-MT retrieves entries from the datastore to support token generation.

4 / 4.1 .. 4.3

kNN-TRANX creates two datastores and uses FAISS for similarity retrieval. Increasing datastore size improves generated-code quality, while placing syntactic and semantic actions in the same datastore substantially reduces quality by introducing noise.

opening

The model uses separate datastores for syntactic and semantic information. Updating the datastore enables efficient fine-tuning with 17k trainable parameters rather than training all 122,205k parameters.

5

A datastore in kNN-MT stores decoder representations as keys and corresponding target characters as values for retrieval. Figure 5 studies the effect of reducing datastore size by removing syntactic knowledge, semantic knowledge, or both.

Limitations

Switching datastores enables rapid updates. Incorporating additional datastores consumes storage space, which may grow with the amount of training data.
