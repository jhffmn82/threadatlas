  • In HYBGRAG: Hybrid Retrieval-Augmented Generation on Textual and Relational Knowledge Bases: HYBGRAG: Hybrid Retrieval-Augmented Generation on Textual and Relational Knowledge Bases is a research paper and proposed retrieval-augmented generation approach for hybrid question answering in semi-structured knowledge bases. It is built around a retriever bank and a critic module. A chat LLM router selects retrieval, using a Text Retrieval Module when hybrid retrieval is not selected and a hybrid retrieval module when it is. The retriever bank handles textual, relational, and hybrid questions, while iterative self-reflection uses validator and commentor feedback to correct question routing, retrieval-module selection, and extracted entities and relations. This creates an interpretable refinement path, similar to CoT, that justifies its decisions. The method begins by routing a question and retrieving information, then validates the result and receives corrective feedback when needed. It can revise its route over additional iterations; in a STARK-Prime example, it starts with text retrieval and switches to hybrid retrieval after rejection of a document. Reported examples show it adding needed entities and removing unsuitable entities or relations. It performs best among evaluated ablations when all design choices are used and approaches oracle performance. HYBGRAG is evaluated for retrieval on STARK and end-to-end RAG on CRAG. It is reported to surpass baselines on hybrid question answering, including Think-on-Graph, AVATAR, and QAGNN on both STARK datasets, and to outperform CoT, text-only and graph-only RAG, concatenated text-and-graph RAG, ReAct, and Corrective RAG on CRAG. It reports a 51% average relative Hit@1 improvement on STARK, with at most 14 API calls and no training, plus stated STARK-MAG and STARK-PRIME retrieval results. On CRAG, it adapts its modules so text retrieval uses web search and a VSS ranker and hybrid retrieval is replaced by graph retrieval. Limitations include use of simple retrieval modules, no significant domain-adaptation advantage, random experience selection for ICL, and worse performance on STARK-Prime than STARK-MAG.

HYBGRAG in HYBGRAG: Hybrid Retrieval-Augmented Generation on Textual and Relational Knowledge Bases

Meng-Chieh Lee, Qi Zhu, Costas Mavromatis, Zhen Han, Soji Adeshina, Vassilis N. Ioannidis, Huzefa Rangwala, Christos Faloutsos · 2025

HYBGRAG: Hybrid Retrieval-Augmented Generation on Textual and Relational Knowledge Bases is a research paper and proposed retrieval-augmented generation approach for hybrid question answering in semi-structured knowledge bases. It is built around a retriever bank and a critic module. A chat LLM router selects retrieval, using a Text Retrieval Module when hybrid retrieval is not selected and a hybrid retrieval module when it is. The retriever bank handles textual, relational, and hybrid questions, while iterative self-reflection uses validator and commentor feedback to correct question routing, retrieval-module selection, and extracted entities and relations. This creates an interpretable refinement path, similar to CoT, that justifies its decisions. The method begins by routing a question and retrieving information, then validates the result and receives corrective feedback when needed. It can revise its route over additional iterations; in a STARK-Prime example, it starts with text retrieval and switches to hybrid retrieval after rejection of a document. Reported examples show it adding needed entities and removing unsuitable entities or relations. It performs best among evaluated ablations when all design choices are used and approaches oracle performance. HYBGRAG is evaluated for retrieval on STARK and end-to-end RAG on CRAG. It is reported to surpass baselines on hybrid question answering, including Think-on-Graph, AVATAR, and QAGNN on both STARK datasets, and to outperform CoT, text-only and graph-only RAG, concatenated text-and-graph RAG, ReAct, and Corrective RAG on CRAG. It reports a 51% average relative Hit@1 improvement on STARK, with at most 14 API calls and no training, plus stated STARK-MAG and STARK-PRIME retrieval results. On CRAG, it adapts its modules so text retrieval uses web search and a VSS ranker and hybrid retrieval is replaced by graph retrieval. Limitations include use of simple retrieval modules, no significant domain-adaptation advantage, random experience selection for ICL, and worse performance on STARK-Prime than STARK-MAG.

Abstract

HYBGRAG is a hybrid question answering method consisting of a retriever bank and a critic module. It automatically refines outputs using critic feedback, adaptively handles questions requiring textual and relational information, and provides an interpretable refinement path. It surpasses all baselines on hybrid question answering benchmarks.

opening

HYBGRAG is proposed to solve hybrid question answering in semi-structured knowledge bases by using textual and relational information simultaneously. It employs a retriever bank and self-reflection to refine question routing, provides an interpretable refinement path, and outperforms baselines on real-world hybrid question answering benchmarks.

3 / 3.1 .. 3.3

HYBGRAG is a method for HQA consisting of a retriever bank and a critic module. It uses iterative routing, retrieval validation, and corrective feedback to address retrieval and question-routing challenges.

4 .. 4.1.2

HYBGRAG is evaluated on STARK and CRAG and achieves the strongest reported results across the retrieval and end-to-end evaluations. Its performance benefits from hybrid retrieval, a retriever bank, critic feedback, iterative self-reflection, and multi-agent design.

opening .. 4.3

HYBGRAG outperforms single-agent and no-agent baselines on HQA and outperforms all compared baselines on CRAG. It uses self-reflection, a retriever bank, and a critic module to refine retrieval decisions, achieving 51% Hit@1 with at most 14 API calls without training.

6

HYBGRAG is proposed for hybrid question answering and uses a critic module to refine question routing through self-reflection. Its retriever bank handles textual, relational, and hybrid questions, and it is reported to outperform all baselines on HQA benchmarks.

Limitations

HYBGRAG can outperform existing RAG and GRAG methods on HQA, but it uses only the simplest retrieval modules. It does not offer significant advantages in domain adaptation and selects random experiences when performing ICL.

B / B.1 .. B.2

HYBGRAG refines its question routing in STARK-Prime. In one example, it first uses text retrieval, then switches to hybrid retrieval after the validator rejects the retrieved document and the commentor provides feedback. It performs best among the evaluated variants when using all design choices and approaches the performance of an oracle.

C / C.1 .. CRAG

HYBGRAG is implemented using examples collected from the STARK training set, with default STARK entity and relation types, ego-graphs of radius no more than two, and four self-reflection iterations. In CRAG, its text retrieval module uses web search and a VSS ranker, while its hybrid retrieval module is replaced by a graph retrieval module.

appendix .. C.1.2

HYBGRAG uses a hybrid retrieval module and refines its extracted entities and relations based on corrective feedback. In the reported examples, it successfully identified when an additional entity was needed and when entities or relations should be removed.

appendix

HYBGRAG is evaluated in CRAG through ablations of its validator and commentor settings. Using context and in-context learning improves its accuracy and reduces hallucination relative to using no context, while oracle settings achieve the strongest reported results. Its critic module provides feedback on incorrect question type, dynamism, domain, entity and relation extraction, and retrieval-module selection.
