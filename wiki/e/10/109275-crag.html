CRAG

benchmark · 1 work · 19 quoted facts · 11 connections
Also called: CRAG benchmark, CRAG–Comprehensive RAG Benchmark, Crag–comprehensive rag benchmark

Abstract written by a model

CRAG is a benchmark for end-to-end RAG performance, combining open-domain question answering and knowledge-base question answering. It provides knowledge graphs from five domains and a testing set of 1,335 textual and relational questions, including simple, comparison, and multi-hop types. Questions are classified by type, dynamism, and domain; topic entities and useful relations are extracted; and either text documents or a knowledge graph is selected as the reference source. For text retrieval, it uses question-based web search and ranks web pages with BAAI/bge-m3. For relational questions, its hybrid retrieval module is replaced with graph retrieval, which builds useful-relation ego-graphs and retrieves reasoning paths from topic entities. A router makes the first decision and can move to another ranked document batch when validation rejects the current output. The workflow proceeds through router reflection, validation, commenting, answer generation, and evaluation against a ground-truth answer. It uses chain-of-thought prompting for generator LLMs and Claude 3 Sonnet to label answers as accurate, incorrect or hallucinated, or missing. Because CRAG lacks retrieval ground truth, corrective feedback is constructed from router actions and evaluation. HYBGRAG, adapted to CRAG, is reported to outperform the listed baselines and achieve the best listed results with Llama 3.1 70B and Claude 3 Sonnet.

CRAG is in one work on this site, HYBGRAG: Hybrid Retrieval-Augmented Generation on Textual and Relational Knowledge Bases. This is the abstract a model wrote of it from that work.

4 .. 4.1.2

CRAG is used as a complementary benchmark for end-to-end RAG performance and includes ODQA and KBQA sub-problems. HYBGRAG achieves the best reported results among the listed methods with both Llama 3.1 70B and Claude 3 Sonnet.

opening .. 4.3

CRAG is used for an end-to-end RAG evaluation in which an LLM evaluator labels answers as accurate, incorrect or hallucinated, or missing. HYBGRAG is adapted to CRAG and outperforms CoT LLM, text-only RAG, graph-only RAG, concatenated-reference RAG, ReAct, and Corrective RAG.

A / A.1 .. A.2

The CRAG benchmark provides knowledge graphs from five different domains as potentially useful references. Its testing set contains 1335 textual and relation questions covering question types including simple, comparison, and multi-hop.

C / C.1 .. CRAG

CRAG uses question-based web search for text retrieval, with a VSS ranker ordering web pages by embedding-space similarity to the question. Its router may proceed to the next ranked batch when the validator rejects the output from the current batch. CRAG replaces hybrid retrieval with graph retrieval for relational questions, extracting useful-relation ego-graphs and retrieving reasoning paths from topic entities to entities in those graphs.

appendix .. C.1.2

CRAG does not provide ground truth for retrieval, so corrective feedback is constructed from the router's action and the evaluation. The unit explains that incorrect graph retrieval may reflect faulty inputs or domain selection, while incorrect text retrieval indicates that the current document batch was not useful.

appendix

CRAG uses Claude 3 Sonnet as its LLM evaluator and chain-of-thought prompting for all generator LLMs. Its dense retrieval and ranking use BAAI/bge-m3, and its implementations of ReAct and Corrective RAG share HYBGRAG's backbone while using different critics.

C.2

CRAG classifies questions by question type, dynamism, and domain, extracts topic entities and useful relations, and selects either the knowledge graph or text documents as a reference source. Its workflow includes router reflection, validation, commenting, generation, and evaluation against a ground-truth answer.
