  • In Reducing hallucination in structured outputs via Retrieval-Augmented Generation: This unit describes a commercial enterprise system that turns natural-language requirements into executable workflows represented as structured JSON. Its central problem is that workflow creation normally requires specialized knowledge, while Generative AI and Large Language Models can hallucinate nonexistent steps, tables, or field values, an obstacle to trustworthy real-world use. The proposed solution is Retrieval-Augmented Generation (RAG), adapted to retrieve structured JSON workflow steps and database tables rather than only factual text. The system first uses a dense retriever, trained in a manner similar to Structure Aware DeNse ReTrievAl (SANTA), to align user requirements with relevant step and table objects. It learns from positive and negative query–object pairs using contrastive loss, and FAISS supports cosine-similarity retrieval at inference. Retrieved items are appended to the user query, after which an LLM produces a JSON workflow through greedy decoding. The retriever and LLM are trained separately: the LLM receives augmented prompts during supervised fine-tuning and assumes required items appear among retrieved suggestions. The work contrasts this approach with Code LLMs and Guided Generation: grammar constraints can help produce valid structures but do not tell a model which enterprise-specific workflow components should be selected. Experiments use in-domain, Human Eval, and out-of-domain datasets built from deployed workflows, user interactions, and deterministic samples. The Human Eval split supplies the final metrics because its inputs are judged more realistic and higher quality. The evaluation compares retriever encoders, StarCoderBase variants, CodeLlama-7B, Mistral-7B-v0.1, and workflow-generation and retrieval results. Results show that fine-tuning a small retriever with combined negative-sampling strategies substantially improves retrieval of steps and tables, whereas simply scaling off-the-shelf encoders has limited benefit. RAG reduces hallucinated steps and tables and supports out-of-domain generalization; StarCoderBase-7B provides the best evaluated StarCoderBase trade-off. The authors identify retriever omissions and difficulty generating IF, TRY, and FOREACH structures as key remaining errors. They favor modular retriever–LLM deployment and conclude that a very small retriever paired with a smaller LLM can preserve performance in limited-resource settings. The system post-processes nonexistent generated steps and asks users to correct outputs, acknowledging that hallucination risk remains. Future work targets joint retriever–LLM training or better-suited architectures.

Abstract

The unit concerns Generative AI systems and their propensity to hallucinate, especially in real-world deployments. It describes an enterprise application that generates workflows from natural language requirements using Retrieval-Augmented Generation (RAG). The system uses RAG to improve the quality of structured workflow output, reduce hallucination, and generalize to out-of-domain settings. It also shows that a small, well-trained retriever can allow a smaller accompanying Large Language Model without reducing performance.

1

The unit concerns using Large Language Models and Generative AI to convert natural language requirements into executable workflows represented as structured JSON documents. It explains that workflows can improve employee productivity but require specialized knowledge, which GenAI may help reduce for novice users. The text describes Retrieval-Augmented Generation as a method for reducing hallucination and improving workflow-generation quality, especially when enterprise-specific steps or database tables are involved. It reports that RAG can enable a smaller LLM and a very small retriever model to perform without loss in performance.

2

The unit explains how Retrieval-Augmented Generation is adapted from retrieving factual information to retrieving JSON objects for structured output generation. It describes the role of the retriever, emphasizing Dense Retrieval and training similar to Structure Aware DeNse ReTrievAl (SANTA) for aligning natural language queries with structured documents. It discusses challenges in structured output tasks, including valid parsing and selecting entities or field values from large, customizable vocabularies. It also contrasts Code LLMs and Guided Generation with the proposed retrieval-based approach, noting that grammar constraints alone do not provide knowledge about which workflow steps to include.

3 .. 3.2

The RAG system retrieves relevant workflow steps and database tables, appends them to a user query, and prompts an LLM to generate a workflow in JSON format using greedy decoding. The retriever is fine-tuned to align natural-language requirements with structured step and table JSON objects, using positive and negative training pairs with contrastive loss. The LLM is trained separately through standard supervised fine-tuning on prompts augmented with retriever suggestions, assuming the required items are present in those suggestions. FAISS indexes the steps and tables for cosine-similarity retrieval at inference time.

4 / 4.1 .. 4.3

The experiments concern a commercial enterprise system that generates workflow JSON documents from natural language requirements using an LLM and a RAG system. The authors create in-domain, Human Eval, and out-of-domain datasets from deployed workflows, user interactions, and deterministic samples, and evaluate them with workflow-generation and retrieval metrics. They fine-tune StarCoderBase variants and compare CodeLlama-7B and Mistral-7B-v0.1, while also comparing retriever encoders. The Human Eval split is used for the final metrics because it provides more realistic and higher-quality inputs than the Test split.

5 / 5.1 .. 5.5

The unit evaluates retriever encoders, retrieval-augmented generation, and StarCoderBase models for workflow generation on the Human Eval and OOD splits. Fine-tuning a small retriever with combined negative sampling strategies substantially improves step and table retrieval, while scaling off-the-shelf encoders provides limited gains. RAG reduces hallucinated steps and tables, with StarCoderBase-7B offering the best trade-off among the evaluated StarCoderBase models. Error analysis identifies retriever omissions and failures to generate structures involving IF, TRY, and FOREACH as important issues, while engineering analysis favors modular deployment of the retriever and LLM.

6

The authors propose deploying a Retrieval-Augmented LLM to reduce hallucination and support generalization in a structured output task. They state that reducing hallucination is necessary for users to adopt real-world GenAI systems. The approach enables deployment in limited-resource settings by coupling a very small retriever with a small LLM. Future work will improve cooperation between the retriever and LLM through joint training or a better-suited model architecture.

Ethical Considerations

Our work proposes an approach to reduce hallucination in structure output tasks. It does not claim that the risk of harm from hallucination is eliminated. The deployed system uses post-processing to identify generated steps that do not exist and urges users to fix the output before continuing their work.
