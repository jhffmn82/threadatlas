Retrieval-augmented generation in multilingual settings

document · 1 work · 0 quoted facts · 0 connections

Abstract written by a model

This work presents and evaluates a zero-shot multilingual retrieval-augmented generation (mRAG) baseline for answering information-seeking queries in users’ languages using retrieved knowledge. Motivated by RAG’s ability to add up-to-date or domain-specific information to large language models and improve factuality, it studies a setting that has received less attention than multilingual open question answering: off-the-shelf multilingual retrieval and generation components used without dedicated task training. The work was done while at Naver Labs Europe and releases code and multilingual-functionality documentation for naver/bergen. The pipeline accepts a query in language Lq, optionally generates or translates a retrieval query, retrieves passages from monolingual or multilingual Wikipedia, reranks them, and prompts an instruction-tuned LLM to answer in the user’s language. It uses BGE-m3 retrieval, BAAI/bge-reranker-v2-m3 reranking, and considers NLLB-600M translation. Wikipedia is split into titled 100-word or 100-character passages; 50 are retrieved and five are supplied to the generator. Experiments compare LLaMA-2-7B-chat, SOLAR-10.7B, Mixtral-8x7B, and Command-R-35B on MKQA and XOR-TyDi QA, with character 3-gram recall and correct-language rate designed to better accommodate verbose answers and named-entity transliteration. The study finds that strong multilingual retrievers and generators alone do not ensure answers in the query language. Explicitly requesting the user’s language and translating the system prompt substantially improve correct-language rates, especially for SOLAR-10.7B and Command-R-35B. Multilingual-by-design models generally produce better non-English responses than English-centric ones. Command-R-35B, BGE-m3, and multilingual Wikipedia retrieval form the strongest overall configuration. Cross-lingual retrieval works well, but non-English results still trail English, with errors arising from retrieval, document reading, generation, and dataset labels. From beginning to end, the work frames mRAG as a needed experimental foundation, specifies and tests its pipeline choices, and concludes that multilingual generation is its weakest component, particularly with mixed-language context. Key remaining problems include code-switching, fluency errors, incorrect reading, irrelevant retrieval, and named-entity handling. It calls for stronger multilingual LLMs, better decoding and evaluation, broader domains beyond Wikipedia, and more retrieval components and tasks; it also notes that Wikipedia-trained retrievers and rerankers may not transfer well to other domains.

Abstract

The work investigates multilingual retrieval-augmented generation (mRAG) for incorporating up-to-date or domain-specific knowledge into large language models and improving factuality. It evaluates mRAG with user queries and a datastore spanning 13 languages, focusing on the components and adjustments needed for a strong baseline pipeline. The findings show that task-specific prompt engineering is needed to enable generation in users’ languages despite high-quality multilingual retrievers and generators. The work also identifies limitations including code-switching, fluency errors, incorrect document reading, and irrelevant retrieval, and releases code for the resulting mRAG baseline pipeline.

Introduction

Retrieval-augmented generation (RAG) has recently emerged as a promising solution for incorporating up-to-date or domain-specific knowledge into large language models (LLMs). It aims to improve LLM factuality, especially in knowledge-intensive tasks. RAG augments user queries with relevant context retrieved from the Internet or a given collection.

Multilingual RAG pipeline

The multilingual RAG pipeline takes an information-seeking user query in language Lq, retrieves relevant context, and generates a response intended to answer the question in the user’s language. Retrieval uses an optional query generation model, a first-stage ranker, and a second-stage reranker over a collection such as Wikipedia, which may be monolingual or multilingual. Generation applies a generator LLM to the query and retrieved context, using instruction-tuning templates and prompting strategies. The pipeline uses multilingual retrievers and rerankers, including BGE-m3, and also considers query translation with NLLB-600M.

The unit describes the multilingual question-answering datasets MKQA, KILT NQ, and XOR-TyDi QA, which primarily ground knowledge in Wikipedia. It explains that both MKQA and XOR-TyDi QA contain context-independent questions with mostly short answer labels, despite being provided with oracle contexts. For evaluation, the authors use lexical matching metrics adapted for verbose, zero-shot LLM outputs, prioritizing recall. They also identify transliteration of named entities as a limitation of word-level matching and motivate adjustments to the evaluation metric.

The unit concerns the 9NQ dataset in the KILT benchmark and the evaluation of model-generated responses. Character n-gram recall is computed by splitting ground-truth labels into tokens, extracting character 3-grams, and measuring how many appear in the generated response. The evaluation also controls for correct language rate, which measures the percentage of outputs written in the user's language. Language detection uses the fasttext library and its lid.176.bin model, but language-rate evaluation is limited to responses longer than 20 characters because short sequences produce many errors.

The retrieval procedure follows Asai et al. (2021b) and Karpukhin et al. (2020), splitting Wikipedia articles into 100-word or 100-character passages and prepending article titles. The system retrieves 50 passages for each evaluation question, then uses a reranker to select five passages for the LLM context. Generation uses greedy decoding, a maximum of 128 new tokens, and an int4-quantized model. Evaluation uses the SQUAD script at the character 3-gram level after lowercasing and removing punctuation and articles.

Results and discussion .. opening

The unit analyzes multilingual RAG performance on MKQA and XOR TyDi QA, focusing on prompting, generator models, retrieval systems, languages, and error sources. Command-R-35B with BGE-m3 and multilingual Wikipedia retrieval provides the strongest overall configuration, although non-English performance remains below English in several respects. Translating the system prompt and explicitly specifying the response language substantially improves Correct Language Rate, while code-switching and named-entity handling remain issues. The analysis also finds that multilingual retrieval works well cross-lingually, but retrieval quality, generation, and dataset labels all contribute to remaining errors.

Conclusion

The work studies retrieval-augmented generation (RAG) in multilingual settings and builds a strong multilingual RAG (mRAG) pipeline as a baseline for future research. It analyzes how each mRAG component affects overall performance and identifies multilingual generation as the weakest part, particularly with mixed-language context. The authors highlight the need for stronger multilingual LLMs, improved decoding strategies, multilingual LLM-based evaluation, and retrieval across multiple domains. They also note that current multilingual retrievers and rerankers rely heavily on Wikipedia-based training data, which may limit their use in other domains.

Limitations

The unit describes limitations of an evaluation using the open question answering task and Wikipedia as the datastore, following common practice in RAG and serving as a first step in mRAG. It notes that other tasks and domains should be considered in future work. The study omitted query reformulation and context post-processing, such as filtering irrelevant passages, because these components were less relevant to the question answering datasets examined. It also considered only a single retriever and reranker model, identified as the strongest open-source multilingual retrieval system available at the time and covering many languages.

Ethics Statement

The work is not anticipated to have a negative societal impact. The authors hope that it will broaden the accessibility of modern NLP. This increased accessibility is intended to extend to other languages.
