In "BERGEN: A Benchmarking Library for Retrieval-Augmented Generation," RAG evaluation is presented as chaotic because studies use inconsistent datasets, collections, metrics, retrieval systems, LLMs, and data-processing choices; the document argues that standardized evaluation is needed to compare RAG methods and components systematically. In "BERGEN: A Benchmarking Library for Retrieval-Augmented Generation," retrieval evaluation is an information retrieval evaluation topic represented by benchmarks and studies including BEIR, TREC Deep Learning, RAGAS, ARES, and work evaluating open-domain question answering. In "Retrieval-augmented generation in multilingual settings," RAG evaluation adapts common practice to zero-shot, verbose LLM answers by prioritizing recall over precision and measuring the percentage of ground-truth tokens represented in responses. In "HYBGRAG: Hybrid Retrieval-Augmented Generation on Textual and Relational Knowledge Bases," retrieval evaluation measures Hit@1, Hit@5, Recall@20, and MRR on STARK-MAG and STARK-PRIME, where HYBGRAG outperforms listed baselines. In "RAGBench: Explainable Benchmark for Retrieval-Augmented Generation Systems," RAG evaluation is an automated evaluation task for comparing and tuning RAG system configurations, addressing a lack of unified criteria and annotated datasets across relevance, faithfulness, hallucination, attribution, adherence, and completeness; the document presents RAGBench and TRACe and notes that LLM-based methods lag a finetuned RoBERTa model. In "Retrieval augmented generation for large language models in healthcare: A systematic review," evaluation metrics assess RAG pipeline performance in various papers and are provided in S3 File. In "VisDoM: Multi-Document QA with Visually Rich Elements Using Multimodal Retrieval-Augmented Generation," retrieval evaluation evaluates VisDoMBench using evidence retrieval performance, measuring evidence extraction with Averaged Normalized Longest Common Subsequence for context windows of k=[1, 5, 10, 20] and correct source-document retrieval at k=5.

Abstract written by a model

RAG evaluation is an automated evaluation task for comparing and tuning RAG system configurations. It matters because unified criteria and annotated datasets are lacking, while evaluation spans relevance, faithfulness, hallucination, attribution, adherence, and completeness. It unfolds from identifying fragmented benchmarks and datasets to presenting RAGBench and TRACe, while noting LLM-based methods lag a finetuned RoBERTa model.

3 sections; each heading opens the text

Abstract

RAG evaluation is described as challenging because unified evaluation criteria and annotated datasets are lacking. The unit presents RAGBench and TRACe as resources for holistic, explainable, and actionable evaluation, and reports that LLM-based evaluation methods struggle to match a finetuned RoBERTa model.

Introduction

RAG evaluation is presented as necessary for comparing and tuning multiple system configurations for particular applications. Existing evaluation work lacks unified benchmarks, uses varying metric definitions, and often relies on small, application-specific datasets.

Related Work .. Finetuned RAG evaluation models

RAG evaluation includes assessing context relevance, answer relevance, faithfulness, hallucination, attribution, retriever relevance, adherence, and completeness. The unit reviews LLM-judge, heuristic, and fine-tuned NLI approaches to this task.
