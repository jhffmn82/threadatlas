“CODERAG-BENCH: Can Retrieval Augment Code Generation?” is a Findings of the Association for Computational Linguistics: NAACL 2025 paper by Zora Zhiruo Wang, Akari Asai, Xinyan Velocity Yu, Frank F. Xu, Yiqing Xie, Graham Neubig, and Daniel Fried. It introduces CODERAG-BENCH, a Python-focused benchmark for retrieval-augmented code generation (RACG), intended to test whether external documents can help language models write correct code. The benchmark spans six programming tasks in four categories: code retrieval, basic programming, open-domain coding, and repository-level coding. It incorporates datasets including HumanEval, MBPP, LiveCodeBench, DS-1000, ODEX, RepoEval, SWE-bench-Lite, and CodeSearchNet. Its resources include 9,000 coding tasks and 25 million documents from competition solutions, tutorials, library documentation, StackOverflow posts, and GitHub repositories. Where possible, it supplies manually annotated canonical documents, evaluates retrieval with NDCG, Precision, and Recall, and evaluates generation through execution-based pass@k. The paper first frames code generation systems as often relying on natural-language prompts and parametric knowledge rather than external programming resources, motivating a systematic RACG benchmark. It then describes the benchmark’s unified interface for canonical and open retrieval, augmented generation, and evaluation. In canonical RACG experiments, the authors evaluate 10 retrievers and 10 generators. Dense and code-specific retrievers generally outperform BM25, though stronger models can impose greater latency and storage costs. Canonical documents often improve generation, notably on basic programming, unfamiliar-library ODEX-hard tasks, and repository-level tasks; they report a 27.4% GPT-4o gain on SWE-Bench. However, benefits vary by task, retriever, and generator. The paper next studies open and mixed retrieval. StackOverflow posts and tutorials can help HumanEval; programming solutions most help ODEX; and local repository context is more useful than external sources for RepoEval. Pre-retrieval chunking generally outperforms post-retrieval chunking and reranking. Overall, high-quality context can substantially improve code generation, but retrievers frequently fail to find useful material and generators have limited context capacity and ability to use retrieved evidence. The authors present CODERAG-BENCH as an initial foundation for future work, while noting its Python focus, limited coverage of debugging, and reliance mainly on vanilla retrieval, reranking, and generation methods.

Abstract

The work introduces CODERAG-BENCH, a benchmark for retrieval-augmented code generation across basic programming, open-domain, and repository-level tasks. It also provides an open datastore containing competition solutions, tutorials, library documentation, StackOverflow posts, and GitHub repositories. The authors evaluate 10 retrievers and 10 language models on retrieval and end-to-end code generation performance. They find that high-quality contexts improve code generation, but retrievers often fail to retrieve useful contexts and generators struggle to use them effectively.

Introduction

The introduction presents CODERAG-BENCH, a benchmark for evaluating retrieval-augmented code generation across six programming tasks in four categories. It provides 9k coding tasks, 25 million documents from five sources, and manually annotated canonical documents for evaluation. The authors report that canonical documents substantially improve code generation, including a 27.4% gain for GPT-4o on SWE-Bench, while retrieval models still struggle with open-domain and repository-level tasks. They also find that StackOverflow and online tutorials, with 200–800-token chunks, can improve some retrieval-augmented code generation results.

It integrates datasets including HumanEval, MBPP, LiveCodeBench, DS-1000, ODEX, RepoEval, SWE-bench-Lite, and CodeSearchNet, and collects retrieval documents from programming solutions, online tutorials, library documentation, StackOverflow posts, and GitHub repositories. Canonical RACG / 3.1 .. 3.4

Canonical RACG evaluates 10 retrieval and 10 generation models on CODERAG-BENCH, covering retrieval, direct code generation, and end-to-end retrieval-augmented code generation. Dense retrievers frequently surpass BM25, while code-specific retrieval models and larger models generally perform better, although they can require substantially more latency and storage. Canonical documents improve many generation results, especially for basic programming problems, unfamiliar libraries in ODEX-hard, and repository-level tasks, while GPT models often gain less on common-library datasets. In full RACG, the best retriever depends on the task and generator, with retrieved context producing particularly strong improvements for weaker models and on SWE-bench-Lite when paired with GPT-4o.

RACG with Open Retrieval

This unit examines RACG with open retrieval and mixed retrieval across HumanEval, ODEX, and RepoEval, using documents from multiple sources and several retrievers with StarCoder2 or GPT-4o. On HumanEval, Stack Overflow posts and, with GIST, tutorials improve results, while mixed documents perform as well as gold documents. On ODEX, programming solutions provide the largest gains and can guide functionally correct library usage, whereas on RepoEval external sources are less useful than local repository context. The unit also compares post-retrieval chunking, reranking, and pre-retrieval chunking, finding that pre-retrieval generally performs best.

Related Work

Neural code generation is described as a crucial task, with increasingly strong code LMs addressing various tasks. Most code LMs rely on natural-language queries and parametric knowledge rather than external programming sources such as tutorials. CODERAG-BENCH integrates datasets and retrieval sources to support systematic studies of retrieval-augmented code generation (RACG). Retrieval augmented generation has mainly been used for text-centric, knowledge-intensive tasks, while the proposed benchmark targets RACG across varied coding tasks and knowledge sources.

The work proposes CODERAG-BENCH, a benchmark for retrieval-augmented code generation across various coding tasks and retrieval sources. Experiments with top-performing retrieval and generation models show that retrieving external documents can greatly benefit code generation. The work finds that retrieval models struggle to find useful documents, while generation models have limited context capacity and RAG abilities, resulting in suboptimal retrieval-augmented code generation results. CODERAG-BENCH is intended to support future advances in this area.

Limitations

The unit concerns retrieval-augmented code generation and its benchmark, CODERAG-BENCH. It presents the work as an initial exploration that could be extended through greater task and language diversity, improved models, and methodological advances. The benchmark aggregates existing code generation tasks but under-explores scenarios such as code debugging and focuses on Python. The experiments mainly use vanilla retrieval, reranking, and generation methods, so the results may not represent all model behaviors.
