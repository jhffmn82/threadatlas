database D in PlanRAG: A Plan-then-Retrieval Augmented Generation for Generative Large Language Models as Decision Makers

Myeonghwa Lee, Seonho An, Min-Soo Kim · 2024

D is a structured database and data source for Decision QA, supplying data for analysis and decision making. It may be a labeled property graph database or a relational database, representing business rules and business situations; in the example, it contains international trade, trading node, country, and related information used to calculate profit changes. D is queried during retrieval through data-analysis queries, executed in SQL or Cypher via RAG interfaces such as LangChain and LlamaIndex. Experiments use MySQL for relational databases and Neo4j for graph databases. D stores data extracted from each game's savefile according to each scenario's schema. Database instances can differ in row count and column values, including LV, building size, and current goods prices. As input to the Locating simulator and its three functions, D is updated with trading-power, flow, and IV values, then returned after profits are calculated. In general, it can be too large for language model input.

Introduction

A database is an input to Decision QA and supplies the data needed for analysis and decision making. In the example, databases contain international trade, trading node, country, and related information from which profit changes must be calculated.

Decision QA task .. Statistics of DQA

A structured database follows a schema and supplies the data used for decision making. In Decision QA, the database may be a labeled property graph database or a relational database.

Methodology: PlanRAG

Database D is queried through data analysis queries during the retrieval process. The queries are executed using SQL or Cypher through RAG interfaces such as LangChain and LlamaIndex.

Experiments / Experimental Setup .. Results and Analysis

The experiments use MySQL as a relational database management system and Neo4j as a graph database management system. PlanRAG-LM performs better than the other LMs for both database types and is particularly more effective on graph databases in Building.

Conclusions

The database represents business rules and business situations for the Decision QA task. The databases are provided in either RDB or GDB form.

Appendix / Data collection

D stores data extracted from each game's savefile according to the DB schema of each scenario.

Data instances

Some instances share the same database D, but not all use the same one. Each database D has a different number of rows and different column values, including values such as LV, building size, and current price of goods.

Locating simulator algorithm

Database D is input to the Locating simulator and its three functions. It is updated with trading-power, flow, and IV values, and is returned after profits have been calculated.
