Abstract written by a model

In PlanRAG: A Plan-then-Retrieval Augmented Generation for Generative Large Language Models as Decision Makers, obj_n is a node whose flow is calculated: find_top_n selects it when eligible, then flow_estimation processes it and adds it to Simulated_n. In PlanRAG: A Plan-then-Retrieval Augmented Generation for Generative Large Language Models as Decision Makers, trade node is a node in an international trade database and a possible merchant location; decisions are evaluated by their effect on profit at a country’s home trading node, and in simulations it may be the object whose flow is calculated.

Locating simulator algorithm

A node can be selected as obj_n by find_top_n when it is not in Simulated_n and has no F connection to another unsimulated node. After selection, flow_estimation processes it and it is added to Simulated_n.

trade node in PlanRAG: A Plan-then-Retrieval Augmented Generation for Generative Large Language Models as Decision Makers

Abstract written by a model

A trade node is a node in an international trade database and a possible merchant location. It matters because decisions are evaluated by their effect on profit at a country’s home trading node. In simulations, a node may be the object whose flow is calculated, with local value, total power, incoming and outgoing connections, inland status, and base trading power on directional edges.

Narrative, section by section written by a model

3 sections; each heading opens the text

Introduction

A trade node is a node in the international trade database and can serve as a location for a merchant. In the example, decisions are evaluated by how they change profit on a country's home trading node.

Algorithm of simulators

A node can be the object whose flow should be calculated, represented by obj_n. Nodes are also represented collectively by the set of nodes and may belong to the set of simulated nodes.

Building simulator algorithm / Business rules in DQA / Prompts for DQA / Previous RAG-based LMs / PlanRAG-based LM

Trading nodes have local_value, total_power, outgoing, ingoing, and an indicator of whether they are inland. Directional source edges connect higher nodes to lower nodes, and trading-node connections have base_trading_power values.
