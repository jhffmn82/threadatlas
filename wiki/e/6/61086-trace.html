TRACE in TRACE the Evidence: Constructing Knowledge-Grounded Reasoning Chains for Retrieval-Augmented Generation

Jinyuan Fang · 2024 · the work’s page · read it where TRACE first appears

Abstract written by a model

TRACE is a framework and method for improving the multi-hop reasoning ability of retrieval-augmented generation models and for identifying supporting evidence in retrieved documents. It processes a multi-hop question without requiring training, using in-context learning to mitigate effects of irrelevant documents. First, its Knowledge Graph Generator independently transforms retrieved documents into a knowledge graph, reducing the lost-in-the-middle issue. Second, its novel Autoregressive Reasoning Chain Constructor iteratively selects connected knowledge-graph triples to build knowledge-grounded reasoning chains. It uses an adaptive chain-termination strategy to determine chain lengths; adaptive-length chains significantly outperform fixed-length chains. Finally, a reader uses the chains directly for answer generation or uses them to select useful documents, supporting triple-based and document-based answer generation. TRACE uses prompts to generate triples, select triples, and generate answers; LLaMA3-7B can generate thoughts or select triples, while LLaMA3, Mistral-7B-v0.1, and Gemma-7B are used as readers. It requires triple-selector logits to define a triple distribution. If logits are unavailable, it can select one triple per step with an option token, producing a single reasoning chain. Across HotPotQA, 2WikiMultiHopQA, and MuSiQue in a zero-shot setting, TRACE-Triple improved average Exact Match by 14.03% over using all retrieved documents, while TRACE-Doc improved it by 13.46%; Exact Match and F1 score are metrics. Its chains generalize across readers. Generating knowledge-graph triples adds indexing cost, measured as 12.34 seconds on HotPotQA development sets, but triple selection with one token helps inference; its HotPotQA inference runtime is 4.13 seconds and is similar to IRCoT there and lower on 2WikiMultiHopQA and MuSiQue.

Narrative, section by section written by a model

12 sections; each heading opens the text

Abstract

TRACE enhances the multi-hop reasoning ability of RAG models by constructing knowledge-grounded reasoning chains from retrieved documents. It achieved an average performance improvement of up to 14.03% over using all retrieved documents across three multi-hop QA datasets.

Introduction

TRACE is a method that constructs knowledge-grounded reasoning chains to improve the multi-hop reasoning ability of retrieval-augmented generation models. It creates a knowledge graph from retrieved documents, autoregressively selects connected triples, and uses the resulting chains either directly for answer generation or to select useful documents. On three multi-hop QA datasets, TRACE-Triple and TRACE-Doc improved average Exact Match by 14.03% and 13.46%, respectively, compared with using all retrieved documents.

TRACE / Overall Framework .. Answer Generation

TRACE answers multi-hop questions by generating a knowledge graph from retrieved documents, constructing reasoning chains, and using those chains to generate answers. It independently processes documents for graph generation to reduce the lost-in-the-middle issue and supports both triple-based and document-based answer generation.

Related Work

TRACE creates a knowledge graph from retrieved documents and constructs reasoning chains for multi-hop reasoning. It uses in-context learning rather than training to mitigate the effects of irrelevant documents, and it focuses on questions with clear answers that may be any words or phrases.

Limitations

TRACE requires access to the logits of the triple selector to define a triple distribution. When those logits are unavailable, TRACE can use the option token output to select one triple at each step, resulting in a single reasoning chain.

Prompts / Prompt for Generating KG Triples .. Prompt for Generating Answers / Demonstration Data / Experimental Details

TRACE uses prompts for generating KG triples, selecting triples, and generating answers. Its reasoning-chain construction process is formalized in Algorithm 1.

Datasets

TRACE aims to identify supporting evidence within retrieved documents. It uses the documents as inputs, performs multi-hop reasoning over them, and generates answers.

Baselines

TRACE is evaluated for its effectiveness in identifying supporting evidence. Its baselines use different methods to identify relevant documents and then provide those documents to the same reader.

Additional Experimental Results and .. MuSiQue

TRACE is evaluated with Mistral-7B-v0.1 and Gemma-7B as readers, and its results are reported as similar to those obtained with LLaMA3. Its reasoning chains are described as generalizing across different readers and as being robust rather than tailored to a specific model.

Chain Constructor .. Chains R

TRACE is evaluated with different document-context sources, reasoning-chain constructor variants, and numbers of reasoning chains. Its performance is reported on HotPotQA, 2WikiMultiHopQA, and MuSiQue.

Effects of Adaptive Chain Termination

TRACE employs an adaptive chain termination strategy in its reasoning chain constructor to automatically determine optimal reasoning-chain lengths. Its adaptive-length versions significantly outperform the Fixed-Length Reasoning Chains variant.

Efficiency Analysis

TRACE is evaluated against IRCoT for indexing and inference latency on development sets. It has higher indexing latency because it generates knowledge-graph triples with additional LLaMA3-7B forward propagations, but its inference runtime is similar to IRCoT on HotPotQA and lower on 2WikiMultiHopQA and MuSiQue. TRACE selects knowledge-graph triples with a single token, which reduces inference latency relative to generating multi-token thoughts.

TRACE in GEAR: Graph-enhanced Agent for Retrieval-augmented Generation

Zhili Shen · 2025 · the work’s page · read it where TRACE first appears

Abstract written by a model

TRACE is an offline method that extracts entities and atomic facts or semantic triples from passages. It relies on Large Language Models to iteratively select pre-filtered candidate triples, constructing reasoning chains that ground answer generation or filter retrieved results; its search space remains limited by the candidate lists for each query.
