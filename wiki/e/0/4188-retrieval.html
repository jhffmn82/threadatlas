Michael Glass, Gaetano Rossiello, Md Faisal Mahbub Chowdhury, Alﬁo Gliozzo · 2021 · the work’s page · read it where retrieval first appears

Abstract written by a model

Slot filling evaluation measures retrieval with R-Precision and Recall@5 on T-REx and zsRE, comparing RAG, BM25, DPR, and KGI methods. RAG training after DPR yields large gains, and DNS plus RAG is strongest. Analysis with random, retrieved, and gold passages shows gold retrieval greatly improves accuracy, while random retrieval harms all systems.

retrieval in Searching for Best Practices in Retrieval-Augmented Generation

Xiaohua Wang, Zhenghua Wang, Xuan Gao, Feiran Zhang, Yixin Wu, Zhibo Xu, Tianyuan Shi, Zhengyuan Wang, Shizheng Li, Qi Qian, Ruicheng Yin, Changze Lv, Xiaoqing Zheng, Xuanjing Huang · 2024 · the work’s page · read it where retrieval first appears

Abstract written by a model

Retrieval is a retrieval component and module within the RAG pipeline. It is generally used when a query needs knowledge beyond the model’s parameters, but not for tasks based entirely on user-provided information. It begins with accurate, clear, detailed queries and transformed or chunked source documents; poor query expression or limited semantic information can reduce performance. The module compares queries with a pre-built corpus and selects top-k relevant documents, then can post-process the retrieved content. Chunking, metadata, semantic alignment, query rewriting, decomposition, HyDE, and methods including BM25, dense retrieval, Contriever, and LLM-Embedder improve retrieval. Dense retrieval combined with BM25 performed best by balancing semantic and exact-term matching; Hybrid with HyDE scored highest but cost more, while Hybrid or Original suits lower latency. Retrieval takes most system processing time and may return irrelevant or many chunks.

Narrative, section by section written by a model

7 sections; each heading opens the text

Query and Retrieval Transformation

Retrieval is improved through accurate, clear, and detailed queries, query-document semantic alignment, transformed source documents, and post-processing of retrieved content.

Retriever Enhancement Strategy

Retrieval is part of the retrieval-augmented generation workflow and includes methods such as BM25, Contriever, LLM-Embedder, query rewriting, query decomposition, HyDE, and hybrid search.

RAG Workflow / Query Classification

Retrieval is generally recommended when a query requires knowledge beyond the model’s parameters. It is not needed for tasks entirely based on information provided by the user.

Chunking

Retrieval is improved by chunking documents into smaller segments, with the goal of increasing precision and avoiding LLM length issues. Smaller chunks can improve retrieval recall, while metadata and advanced chunking techniques can further improve retrieval quality.

Retrieval Methods

The retrieval module selects the top-k relevant documents from a pre-built corpus according to similarity between the query and documents. Its performance can be negatively affected when original queries have poor expression or limited semantic information.

Comprehensive Evaluation .. Results and Analysis

The retrieval module performed best when dense retrieval was combined with BM25, because semantic matching and exact term matching compensate for each other's weaknesses. Hybrid with HyDE achieved the highest RAG score but incurred greater computational cost, while Hybrid or Original were recommended when lower latency is needed.

Discussion / Best Practices for Implementing RAG .. Multimodal Extension

Retrieval accounts for the majority of processing time in the RAG system. Retrieval methods can provide information from verified multimodal materials, reduce computation when the answer or image already exists in stored materials, and be improved by enlarging and enhancing retrieval sources.
