The document situates FLARE among retrieval-augmented, iterative refinement, adaptive retrieval, and browser-enhanced language-model approaches. It also notes limits: FLARE did not significantly improve Wizard of Wikipedia or ELI5, and repeated retrieval and regeneration add computational cost. It proposes future work on better active-retrieval strategies and architectures that can integrate retrieved information more efficiently.

Abstract

The text concerns large language models (LMs), which can understand and generate language but often produce factually inaccurate output. It describes retrieval augmented LMs that use external knowledge resources, noting that most retrieve information only once from the input. The work presents active retrieval augmented generation and proposes Forward-Looking Active REtrieval augmented generation (FLARE), which repeatedly predicts upcoming sentences, retrieves relevant documents, and regenerates sentences containing low-confidence tokens. FLARE achieves superior or competitive performance across four long-form knowledge-intensive generation tasks/datasets.

Introduction

The unit concerns generative language models and the challenge of hallucination, proposing retrieval during generation to provide needed external knowledge. It introduces Forward-Looking Active REtrieval augmented generation (FLARE), which generates a temporary future sentence, retrieves documents when that sentence contains low-probability tokens, and regenerates it using the retrieved information. FLARE is designed for long-form tasks and can be applied to existing language models at inference time without additional training. Evaluations using text-davinci-003 on four datasets found that FLARE achieved superior or competitive performance against single-time and multi-time retrieval baselines.

2 .. 2.3

The unit defines Retrieval Augmented Generation for producing answers from a user input and a document corpus. It explains that a retriever returns documents for a query and that a language model conditions on the user input and retrieved documents. Single-time retrieval augmented generation retrieves once using the user input and generates the complete answer. Active retrieval augmented generation interleaves retrieval and generation by formulating queries from the user input and previously generated output, while retaining only the current retrieval results as context.

3 .. 3.3

Forward-Looking Active REtrieval Augmented Generation (FLARE) is a framework for active retrieval augmented generation that retrieves information when the language model lacks necessary knowledge and forms queries around future generation needs. It introduces FLAREinstruct, which uses retrieval instructions to prompt search queries during answer generation, and FLAREdirect, which uses the model’s provisional next sentence to decide whether and what to retrieve. FLAREdirect triggers retrieval when any token in the temporary next sentence has probability below a threshold, then regenerates the sentence using retrieved documents. The unit describes masked-sentence and generated-question approaches for formulating retrieval queries and reports an implementation using GPT-3.5, BM25, and Bing.

4

The section on Multi-time Retrieval Baselines formulates existing passive multi-time retrieval augmented LMs within the authors' framework. It introduces three baseline categories based on when and what to retrieve: Previous-window approaches, Previous-sentence approaches, and Question decomposition approaches. Previous-window approaches retrieve every fixed number of tokens, Previous-sentence approaches retrieve once per sentence, and Question decomposition approaches retrieve when a generated sub-question appears. The section notes that these approaches may use unsuitable queries, retrieve inefficiently, or require task-specific prompt engineering.

5 .. Open-domain summarization

The unit describes the experimental setup for evaluating FLARE on knowledge-intensive tasks using few-shot in-context learning and up to 500 examples per dataset. It covers multihop QA with 2WikiMultihopQA, commonsense reasoning with StrategyQA, long-form QA with ASQA and ASQA-hint, and open-domain summarization with WikiAsp. The evaluation uses task-specific metrics, including exact match, token-level scores, Disambig-F1, ROUGE, DR, named entity-based F1, and UniEval. FLARE is compared with no retrieval, single-time retrieval, and previous-window retrieval across the datasets.

6 .. 6.2

This unit reports experimental results for FLARE across 2WikiMultihopQA, StrategyQA, ASQA, ASQA-hint, and WikiAsp, comparing it with single-time retrieval and several multi-time retrieval baselines. FLARE outperforms the baselines across the reported tasks and datasets, with especially strong gains on 2WikiMultihopQA. Ablations show that forward-looking retrieval using the next sentence is more effective than retrieval based on previous context, while active retrieval performs best when applied selectively. The results also show that implicit masking-based and explicit question-generation query formulation achieve similar performance.

7

The unit positions FLARE within work on single-time and multi-time retrieval-augmented LMs. It distinguishes FLARE from iterative retrieval and refinement methods in text and code generation based on generation granularity and retrieval strategies. It notes that adaptive retrieval has been studied for single-time retrieval using question popularity or generation probabilities, whereas FLARE targets long-form generation requiring active information access. It also compares FLARE with browser-enhanced LMs such as WebGPT and WebCPM, noting that FLARE uses text-based retrievers but could be combined with a browser.

8

The unit concerns an active retrieval augmented generation framework for aiding long-form generation with retrieval augmentation. The framework decides when and what to retrieve during generation, using forward-looking active retrieval to identify low-confidence tokens in an upcoming sentence, retrieve relevant information, and regenerate the next sentence. Experimental results on four tasks and datasets demonstrate the effectiveness of the methods. Future directions include better active retrieval strategies and efficient language model architectures for active information integration.

9

The unit reports that FLARE did not provide significant gains on Wizard of Wikipedia or ELI5. Wizard of Wikipedia has relatively short outputs, while ELI5 requires long-form answers and presents grounding and evaluation difficulties. The text also notes that interleaving generation and retrieval increases computational overhead because language models must be activated multiple times and prior activations may need recomputation. Special architectures that independently encode retrieved documents and the input or generation could potentially reduce this cost.
