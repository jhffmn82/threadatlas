method · 5 works · 22 quoted facts · 9 connections

  • In "Enhancing Retrieval-Augmented Large Language Models with Iterative Retrieval-Generation Synergy," ReAct is a reasoning method that interleaves reasoning, retrieval actions, and observations for iterative information search.
  • In "Generate-then-Ground in Retrieval-Augmented Generation for Multi-hop Question Answering," ReAct is a generation-with-retrieval method that interleaves retrieval, question generation, and knowledge incorporation as a strong ChatGPT baseline.
  • In "PlanRAG: A Plan-then-Retrieval Augmented Generation for Generative Large Language Models as Decision Makers," ReAct is a decision-making prompt structure using Thought-Action-Observation prompts for language models.
  • In "TableRAG: A Retrieval Augmented Generation Framework for Heterogeneous Document Reasoning," ReAct is a prompt-based reasoning-and-acting framework with external knowledge sources, evaluated against TableRAG and NaiveRAG.
  • In "HYBGRAG: Hybrid Retrieval-Augmented Generation on Textual and Relational Knowledge Bases," ReAct is a self-reflective baseline that performs search and extraction actions through action-observation-thought iterations.

ReAct in TableRAG: A Retrieval Augmented Generation Framework for Heterogeneous Document Reasoning

Xiaohan Yu, Pu Jian, Chong Chen · 2025

ReAct is a prompt-based reasoning-and-acting framework with external knowledge sources. It unfolds through repeated execution steps, performing reasoning at every step before reaching a final decision. It performs better than NaiveRAG on multi-source data, but on single-source tabular reasoning its multi-turn decomposition can over-fragment work and cause cascading failures. Its execution-step distribution is comparable to TableRAG’s, yet it takes more steps, has greater time overhead and latency, and is markedly inferior overall. It lacks context-aware query decomposition and code execution simulation, often using elaborate reasoning where one structured inquiry could suffice.

Narrative, section by section

3 sections; each heading opens the text

5 / 5.1 / 5.1.1 .. 5.3

ReAct is evaluated as a prompt-based framework that combines reasoning and acting with external knowledge sources. It performs better than NaiveRAG on multi-source data but degrades on single-source tabular reasoning, where multi-turn decomposition can cause over-fragmentation and cascading failures. Its total latency is 17.70 seconds on WikiTQ and 45.65 seconds on HeteQA.

6 / 6.1 .. 6.2

ReAct exhibits an execution-step distribution comparable to TableRAG, but its overall performance remains markedly inferior. It performs reasoning at every step and consumes more steps before reaching a final decision, resulting in greater time overhead and higher latency than TableRAG.

7 / 7.1 .. 7.2

ReAct lacks mechanisms for context-aware query decomposition and code execution simulation. It often performs unnecessarily elaborate reasoning for problems that could be answered with a single structured inquiry. TableRAG outperforms it in most evaluated domains.
