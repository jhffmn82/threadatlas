Narrative, section by section

Abstract

The unit examines retrieval-augmented generation (RAG) approaches and combinations for enhancing large language models. It finds that existing query-dependent retrieval methods can be complex to implement and can prolong response times. Through extensive experiments, the authors propose RAG deployment strategies that balance performance and efficiency. The unit also reports that multimodal retrieval techniques improve question-answering about visual inputs and accelerate multimodal content generation through a "retrieval as generation" strategy.

Introduction

The introduction explains that generative large language models can produce outdated information or fabricated facts, while retrieval-augmented generation combines pretrained models with retrieval to improve robustness and enable domain-specific applications without updating model parameters. It describes the RAG workflow, including query classification, retrieval, reranking, repacking, summarization, document chunking, embedding selection, vector databases, and LLM fine-tuning. The study systematically compares RAG methods and combinations to identify practices that balance effectiveness and efficiency across application scenarios. It also presents an evaluation framework and reports that multimodal retrieval can improve visual question answering and accelerate multimodal content generation through retrieval as generation.

Related Work

The unit concerns the accuracy of responses generated by Large Language Models (LLMs), including ChatGPT and LLaMA. It states that increasing model size does not fundamentally solve hallucinations, particularly in knowledge-intensive and specialized-domain tasks. Retrieval-augmented generation addresses these challenges by retrieving relevant documents from external knowledge bases to provide accurate, real-time, domain-specific context. Prior work has improved the RAG pipeline through query and retrieval transformations, retriever and generator fine-tuning, and better interaction among queries, retrieval, and generation.

Query and Retrieval Transformation

The section on Query and Retrieval Transformation explains that effective retrieval depends on accurate, clear, and detailed queries, although semantic differences between queries and relevant documents can remain after embedding conversion. It describes query transformation methods, including Query2Doc and HyDE, which generate pseudo-documents, and TOC, which decomposes queries into subqueries and aggregates retrieved content. It also discusses transforming retrieval source documents through LlamaIndex-generated pseudo-queries and contrastive learning, as well as post-processing retrieved documents with summarization and compression techniques. These approaches aim to improve query-document matching, retrieval performance, generator output, and context efficiency.

Retriever Enhancement Strategy

Retriever Enhancement Strategy concerns methods for improving retrieval performance in retrieval-augmented generation. It discusses document chunking, embedding, retrieval, reranking, query processing, vector databases, summarization, repacking, evaluation, and fine-tuning. LlamaIndex is described as optimizing chunking methods such as Small2Big and sliding windows. The retrieval-augmented generation workflow study investigates the contribution of each component through extensive experimentation and identifies empirically best-performing selections.

Retriever and Generator Fine-tuning

Fine-tuning in the RAG framework optimizes retrievers and generators. Some studies fine-tune generators to use retrieved context more effectively, while others train retrievers to find passages beneficial to generators. Holistic approaches fine-tune both components together to improve overall performance, despite greater complexity and integration challenges. Surveys cover RAG applications in text generation, LLM integration, multimodal systems, and AI-generated content, but selecting an appropriate algorithm for practical implementation remains difficult.

RAG Workflow / Query Classification

The RAG workflow describes query classification as its initial module for deciding whether queries need retrieval. Query classification distinguishes tasks that can be answered from user-provided information from those that may require knowledge beyond an LLM’s parameters. The authors categorize 15 task types and create a dataset of 111K samples to train a classifier for this decision. Queries classified as requiring retrieval proceed through the RAG modules, while other queries are handled directly by LLMs.

Chunking

The unit concerns Chunking documents to improve retrieval precision and avoid length issues in LLMs. It compares token-level, semantic-level, and sentence-level approaches, selecting Sentence-level Chunking for the study because it balances simplicity and semantic preservation. It examines Chunk Size, Chunking Techniques, Metadata Addition, and Embedding Model as four dimensions of chunking. The study selects LLM-Embedder based on the evaluation module of FlagEmbedding for its balance of performance and size, while deferring detailed metadata analysis and related comparisons to future work and Appendix A.2.

Vector Databases

The unit concerns vector databases and their evaluation for research use. Vector databases store embedding vectors with metadata and support efficient document retrieval through indexing and approximate nearest neighbor methods. Five open-source vector databases, Weaviate, Faiss, Chroma, Qdrant, and Milvus, were compared using four criteria: multiple index types, billion-scale vector support, hybrid search, and cloud-native capabilities. Milvus was identified as the most comprehensive solution because it met all four criteria and outperformed the other evaluated options.

Retrieval Methods

The retrieval module selects top-k relevant documents from a pre-built corpus, while a generation model uses them to formulate responses. The study evaluates query rewriting, query decomposition, and pseudo-documents generation with LLM-Embedder as the query and document encoder. It compares BM25 sparse retrieval, Contriever dense retrieval, and hybrid search on the TREC DL 2019 and 2020 passage ranking datasets. Hybrid Search with HyDE is recommended for performance, while hybrid search with the original embedding is recommended when efficiency and latency are prioritized.

Reranking Methods

Reranking Methods improve retrieval by reordering documents so that the most relevant information appears first. The unit compares DLM Reranking, which uses classification with deep language models, and TILDE Reranking, which uses query-term likelihoods for greater efficiency. Experiments on the MS MARCO Passage ranking dataset used monoT5, monoBERT, RankLLaMA, and TILDEv2. The text recommends monoT5 as a balance of performance and efficiency, RankLLaMA for best performance, and TILDEv2 for the fastest experience on a fixed collection.

Document Repacking

Document Repacking concerns how the order of documents affects subsequent processes such as LLM response generation. It introduces a compact repacking module used after reranking, with three methods: forward, reverse, and sides. Forward orders documents by descending reranking relevance scores, while reverse orders them ascending. Inspired by Liu et al. (2024a), the sides method places relevant information at the head or tail and is selected as the default method after testing.

Summarization

This unit concerns summarization methods for retrieval-augmented generation (RAG), where redundant information and long prompts can reduce response accuracy and slow inference. It distinguishes extractive methods, which select important sentences, from abstractive methods, which synthesize information across documents, and focuses on query-based methods. Recomp and LongLLMLingua are evaluated on NQ, TriviaQA, and HotpotQA; Recomp is recommended for its strong performance, while LongLLMLingua is considered an alternative because of its better generalization capabilities.

Generator Fine-tuning

This unit examines fine-tuning the generator in a RAG system while leaving retriever fine-tuning for future work. It compares training with relevant documents, randomly retrieved documents, mixtures of both, and duplicated relevant documents, using Llama-2-7B as the base model. The study evaluates ground-truth coverage on QA and reading comprehension datasets and finds that Mgr, trained with mixed relevant and random contexts, performs best with gold or mixed contexts. The results suggest that including a few relevant and randomly selected documents during training improves robustness to irrelevant information while preserving effective use of relevant contexts.

Searching for Best RAG Practices

The section investigates best RAG practices by sequentially optimizing individual modules and selecting the most effective alternatives. It uses Llama2-7B-Chat as the generator, with each query augmented by a few randomly selected and relevant documents. Milvus builds a vector database containing 10 million English Wikipedia texts and 4 million medical data texts. The study also examines the impact of removing the Query Classification, Reranking, and Summarization modules.

Comprehensive Evaluation .. Results and Analysis

The Comprehensive Evaluation assesses RAG systems across Commonsense Reasoning, Fact Checking, Open-Domain QA, MultiHop QA, and Medical QA using task-specific metrics and five RAG capabilities. Results show that query classification improves the average score and reduces latency by avoiding unnecessary retrieval, while hybrid retrieval, reranking, reverse repacking, and Recomp summarization improve response quality. Hybrid with HyDE achieves the highest reported RAG score of 0.58 but requires 11.71 seconds per query, whereas monoT5 is the strongest tested reranker. Recomp generally outperforms LongLLMLingua because it preserves source-content integrity, although removing summarization can reduce latency.

Discussion / Best Practices for Implementing RAG .. Multimodal Extension

This unit presents best practices for implementing retrieval-augmented generation (RAG), distinguishing a highest-performance configuration from a more efficient balanced configuration. It recommends empirical comparison, module integration, and evaluation of module combinations because the best methods may vary across tasks and contexts. It also describes a multimodal extension of RAG using text2image and image2text retrieval with paired images and textual descriptions. Experiments using PartiPrompts, stable diffusion, CC3M, and CLIP Similarity found that retrieval as generation reduced time while maintaining image quality and could be improved by expanding retrieval sources.

Conclusion

This study identifies optimal practices for implementing retrieval-augmented generation to improve the quality and reliability of content produced by large language models. It systematically assesses potential solutions for each module within the RAG framework and recommends the most effective approach for each module. The study introduces a comprehensive evaluation benchmark for RAG systems and conducts extensive experiments to compare alternatives. Its findings deepen understanding of retrieval-augmented generation systems and establish a foundation for future research.

Limitations

The study evaluates the impact of various methods for fine-tuning LLM generators. It notes that previous studies demonstrated the feasibility of jointly training the retriever and generator, but this possibility was left for future work. The study uses modular design to simplify the search for optimal RAG implementations and limits its evaluation to representative chunking techniques because of the costs of constructing vector databases and conducting experiments. It discusses RAG in NLP and image generation and identifies speech and video as possible areas for future exploration.
