ThreadAtlas

A knowledge graph you can read

ThreadAtlas reads a pile of documents and builds a knowledge graph a person can walk. Every page on this site was written from that graph: every fact links to the verbatim quote it came from, and every quote opens the source text at the spot it was taken. The summaries, abstracts and section notes around the facts are written by a model.

Nothing is merged. When the same person, place or idea appears in two works, one page links both, and each claim stays with the work that made it. Connections between entities are facts a work states, so every line in a figure opens to its quotes.

The same pipeline answers questions from the graph; its benchmark results are below.

About

ThreadAtlas is Justin Hoffman's IT 494 project in the M.S. in Computer Science at Illinois State University, advised by Dr. Xing Fang.

The intent is a wiki that builds itself from documents: one a person can read and walk, where every fact can be traced to the words it came from. Language models do the reading; code checks every quote against the source before it is kept. The same graph answers questions, and its scores on public benchmarks show the representation holds up. The wiki is the goal; the benchmarks back it.

This first version holds books and papers: research on retrieval-augmented generation and knowledge graphs, and public-domain literature. The graph also holds the LongMemEval benchmark's conversation histories, which are not published here.

How it works

  1. Extractor. Each file is read on its own and cut into dated units: chapters, sections, or chat turns. Every boundary must copy text found on the cited line.
  2. Ingestor. Per document: the entities, the facts with verbatim quotes, a narrative cell per entity per unit, and abstracts. A fact is kept only if its quote is found in its unit's text.
  3. Global layer. Which entities in different documents are the same thing? A judge model rules on each offered pair; a parent links the instances without merging them. Bodies of work are found the same way.
  4. Retrieval. A question is answered from the graph: vector and keyword search fused by rank, each hit packed with the passage its facts came from.
  5. Wiki. This site, rendered from the store by one deterministic pass: no page is written by hand and no model is called.
