BERGEN: A Benchmarking Library for Retrieval-Augmented Generation

David Rau, Hervé Déjean, Nadezhda Chirkova, Thibault Formal, Shuai Wang, Stéphane Clinchant, Vassilina Nikoulina · 2024 · 17 sections
"BERGEN: A Benchmarking Library for Retrieval-Augmented Generation" by David Rau, Hervé Déjean, Nadezhda Chirkova, Thibault Formal, Shuai Wang, Stéphane Clinchant, Vassilina Nikoulina (2024), licensed CC BY. Shown here as extracted text, with facts drawn from it. https://doi.org/10.18653/v1/2024.findings-emnlp.449

“BERGEN: A Benchmarking Library for Retrieval-Augmented Generation,” by David Rau, Hervé Déjean, Nadezhda Chirkova, Thibault Formal, Shuai Wang, Stéphane Clinchant, and Vassilina Nikoulina, presents an open-source Python framework and a systematic RAG benchmark study. RAG combines a ranking system, which indexes and retrieves passages for a user input, with a language model that generates an answer using the input and retrieved context. The paper frames RAG as a way to supplement static, potentially inaccurate LLM knowledge, while stressing that comparisons have been difficult because studies vary in datasets, collections, metrics, retrievers, rerankers, and models. BERGEN standardizes processing, indexing, retrieval, generation, training, and evaluation. It supports sparse, dense, decoder-based, and traditional retrievers; cross-encoder rerankers; open-weight LLMs; QA datasets; and training configurations. Its reproducible retrieval setting uses a fixed KILT Wikipedia collection of about 24.8 million 100-word passages. Answers can be evaluated with surface metrics, BEM, GPT-4, and LLMeval, which uses SOLAR-10.7B-Instruct-v1.0 to judge whether generated and reference answers are equivalent. The study spans more than 500 experiments, including over 450 results across 10 datasets. It finds that LLMeval aligns most closely with GPT-4-as-a-judge and that semantic evaluation complements surface matching. Better retrieval generally improves generated answers, and reranking is particularly important; strong MTEB retrievers perform better in retrieval and generation, though reranking reduces differences between methods. Retrieval’s value is dataset-dependent: NQ is judged suitable because stronger retrieval and Oracle retrieval improve results, whereas closed-book performance exceeds retrieval settings on ELI5 and WoW. Retrieval evaluation uses Recall@5 mapped from KILT document annotations to the fixed passage split. The paper also finds that LLMs of any size can benefit from retrieval, while NQ QLoRa fine-tuning helps smaller models most and narrows their gap with larger ones. Multilingual experiments across 12 non-English languages use BGE-M3 retrieval, BGE-reranker-v2-m3, Command-R-35B, MKQA, and XOR-TyDi QA; multilingual Wikipedia retrieval is usually beneficial, but the best datastore depends on the dataset. The work closes by offering BERGEN’s modular framework, data, and runs while noting limits: computational constraints, one Wikipedia collection, mostly zero-shot QA evaluation, and limited scope beyond QA RAG.

Abstract body

The unit concerns Retrieval-Augmented Generation (RAG), which enhances Large Language Models with external knowledge. It examines the difficulty of comparing RAG approaches because experiments vary across datasets, collections, metrics, retrievers, and LLMs. The work studies best practices for systematic RAG evaluation and presents BERGEN, an end-to-end library for reproducible RAG research. It benchmarks retrievers, rerankers, and LLMs for question answering and analyzes existing RAG metrics and datasets.

Introduction body

The unit explains that Large Language Models store extensive pretraining knowledge in their weights and can be prompted for Question Answering, but this knowledge is static, difficult to update, and may be inaccurate or outdated. Retrieval-Augmented Generation addresses these limitations by supplying relevant information from an external collection, although RAG pipelines involve many interacting design choices. The text introduces BERGEN, a Python library for reproducible end-to-end RAG experiments, and describes a BERGEN benchmark study covering more than 500 experiments across datasets, metrics, retrievers, rerankers, and LLMs. The study finds that semantic evaluation, strong retrieval systems, careful benchmark selection, and retrieval itself are important, and that LLMs of any size can benefit from retrieval.

Related Work body

The unit reviews RAG libraries and argues that existing tools provide insufficient flexibility, component coverage, or analysis for research environments. It describes fragmented experimental setups across RAG studies, involving different datasets, collections, metrics, retrieval systems, and LLMs, which prevents systematic comparison. It emphasizes that retrieval quality, including ranking and reranking, remains underexplored relative to the LLM component. It also identifies inconsistent data processing and calls for a unified framework to systematically train and evaluate RAG systems.

Task Definition body

RAG consists of a ranking system R and a parametric generative language model θ. The ranking system first builds a search index I from a collection and then searches it at request time using the user input x. This search produces relevant context segments c, which may be sentences, passages, or entire documents, although the work focuses on passages. The language model generates a response r from x and c embedded in a model-specific instruction template i.

Benchmarking Library BERGEN .. 4.7 body

BERGEN is an open-source Python library for standardizing end-to-end Retrieval-Augmented Generation experiments, including data processing, indexing, retrieval, generation, training, and evaluation. It supports traditional, sparse, dense, and decoder-based retrievers, cross-encoder rerankers, open-weight LLMs, numerous QA datasets, and multiple training configurations. BERGEN is built on the Hugging Face Hub and uses a fixed KILT Wikipedia collection of approximately 24.8 million 100-word passages for reproducible retrieval experiments. It evaluates generated answers with surface-based metrics, BEM, GPT-4, and LLMeval, an LLM-based answer equivalence evaluator.

Experiments .. 5.6 body

BERGEN presents a large systematic study of retrieval-augmented generation, comparing retrievers, rerankers, large language models, datasets, and evaluation metrics. The experiments find that LLMeval most closely correlates with GPT-4-as-a-judge, while retrieval improves performance substantially on some datasets but harms or fails to improve it on others. Higher-quality retrieval and reranking generally improve downstream generation, although retrieval gains are not consistently related to LLM size. Fine-tuning on NQ with QLoRa benefits smaller models most and narrows the gap between the smallest and largest models.

6 .. Limitations body

The unit presents BERGEN, a library for benchmarking RAG systems through systematic experiments across retrieval, reranking, language models, and datasets. It concludes that semantic evaluations complement surface-matching metrics, retrieval quality strongly affects RAG response generation, and rerankers are especially important. The authors report that large language models of any size can benefit from improved retrieval methods and provide a modular framework, data, and runs to support reproducibility. The work is limited by computational constraints, reliance on a single Wikipedia-based collection and mostly zero-shot evaluation, and a primary focus on QA RAG.

A appendix

The unit presents the main results of evaluating different LLMs with context provided through different retrieval systems. The evaluation covers 10 datasets. Table 4 contains the results of more than 450 experiments.

B appendix

The unit analyzes whether ELI5 and WoW are suitable for RAG evaluation in the benchmark, using different retrievers and SOLAR 10.7B and Llama2 70B. On ELI5, the Closed Book setting outperforms Oracle retrieval, while retrievers have low retrieval performance but sometimes improve generation quality relative to Oracle. On WoW, the Closed Book setting also outperforms retrieval-based systems, and it is unclear why the dialogue task should depend on Wikipedia knowledge. NQ is presented as a suitable RAG dataset because stronger retrieval systems produce increasing benefits and Oracle retrieval achieves the highest performance.

C appendix

The unit describes retrieval evaluation on KILT. KILT provides passage- and document-level annotations of gold documents containing answers, but these annotations are not compatible with the 100-word passage split. The evaluation maps passages to document-level ranking annotations to indicate whether a retrieved passage belongs to a relevant document. Retrieval effectiveness is measured with Recall@5 across KILT datasets containing ranking labels, using models discussed in Section 5.3, with a broader NQ evaluation in Appendix D.

D appendix

Retrieval Analysis examines how retrieval quality affects generation. It compares modern SoTA retrievers, including models from the MTEB benchmark fine-tuned on datasets such as NQ, using retrieval performance and generation quality with and without re-ranking. SoTA MTEB models perform better on both retrieval and generation, while re-ranking narrows the gap between approaches. The analysis notes that these results do not measure the zero-shot performance of the RAG pipeline because learned retrievers may not generalize to out-of-domain collections.

E appendix

The unit describes zero-shot evaluation of large language models using a shared prompt with retrieved passages or a closed-book variant, across ASQA, KILT QA tasks, POPQA, SCIQ, WIKIQA, and TruthfulQA. It compares retrieval systems including BM25, RetroMAE, SPLADE-v3, dense retrievers, and reranked variants, reporting Match, LLMeval, and R@5 results. On KILT retrieval tasks, SPLADE-v3+RR achieves the strongest listed average retrieval results among BM25, RetroMAE, and SPLADE-v3 variants. Additional experiments on KILT NQ with SOLAR-10.7B show that E5-large-v2 has the highest listed R@5 after reranking, while reranking can reduce E5 retrieval effectiveness.

F appendix

LLMeval is an LLM-based method for evaluating whether a generated answer is equivalent to a reference answer. It uses SOLAR-10.7B-Instruct-v1.0 with a question, golden answer, and generated answer, asking the model to judge correctness. The evaluation prompt requests a binary response, and outputs outside the expected labels are mapped to false. vLLM is used to speed inference, while extracting true/false logits produced comparable results to direct single-token generation.

G appendix

The unit concerns Training Details in a document. It introduces Table 8, which lists the Hyperparameters used for the fine-tuning experiments. No specific hyperparameters are provided in this unit.

H appendix

This unit describes BERGEN’s support for multilingual retrieval-augmented generation (RAG) across 12 non-English languages, including multilingual retrieval, generation, datasets, datastores, metrics, and results. BGE-M3 is used for dense multilingual retrieval and BGE-reranker-v2-m3 is identified as the reranker, while Command-R-35B serves as the multilingual generator. Experiments use MKQA and XOR-TyDi QA with English, user-language, concatenated, and all-language Wikipedia datastores. Results show that multilingual Wikipedia retrieval is beneficial in most cases, that the best datastore depends on the dataset, and that character 3-gram recall is more robust than word-level matching for transliterations.
