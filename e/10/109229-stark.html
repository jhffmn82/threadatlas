STARK in HYBGRAG: Hybrid Retrieval-Augmented Generation on Textual and Relational Knowledge Bases

Meng-Chieh Lee, Qi Zhu, Costas Mavromatis, Zhen Han, Soji Adeshina, Vassilis N. Ioannidis, Huzefa Rangwala, Christos Faloutsos · 2025

STARK is a system requiring design choices, using Claude 3 by default plus a router, validator, and commentor. It uses prompts to route an initial decision, extract topic entities and useful relations, assess whether a knowledge graph or text documents can narrow search, and revise decisions when retrieved documents are incorrect. It is evaluated on API calls, token consumption, ablations, and HYBGRAG results, including improvements in Hit@1.

opening .. 4.3

STARK is evaluated for API calls and token consumption across HYBGRAG's components. Compared with AVATAR, which requires at least 500 API calls during training, HYBGRAG achieves a relative 24% improvement in Hit@1 with only 2 API calls for its hybrid retrieval module.

6

STARK is a setting on which HYBGRAG is applied. In this application, HYBGRAG achieves an average relative improvement of 51% in Hit@1.

appendix .. C.1.2

STARK is evaluated through ablation settings involving context, prompting, and oracle information on STARK-MAG and STARK-PRIME. The unit also describes baseline implementations used for STARK, including ada-002 for dense retrieval and ranking.

C.2

STARK uses prompts for first-decision routing, reflection, validation, and commenting. Its workflow extracts topic entities and useful relations, determines whether the knowledge graph or text documents can narrow the search, and revises decisions when retrieved documents are incorrect.
